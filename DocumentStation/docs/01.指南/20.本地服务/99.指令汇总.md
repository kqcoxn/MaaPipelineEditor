# LocalBridge 指令汇总

LocalBridge 的可执行文件名为 `mpelb`，本页汇总了目前所有可用的安装、更新、命令行参数以及配置管理命令，方便您在部署和日常使用时快速查阅。

::: tip
命令行参数的优先级高于配置文件。您可以用配置文件保存常用配置，再用命令行参数临时覆盖。
:::

文件根目录按 `--root`、配置文件 `file.root`、启动工作目录的顺序确定。`--root` 的相对路径以启动工作目录为基准，配置文件中的相对路径以配置文件所在目录为基准；命令行值不会写回配置文件。

## 安装与更新

::: code-group

```shell [Windows (PowerShell)]
irm https://raw.githubusercontent.com/kqcoxn/MaaPipelineEditor/main/scripts/install/install.ps1 | iex
```

```shell [Linux/macOS]
curl -fsSL https://raw.githubusercontent.com/kqcoxn/MaaPipelineEditor/main/scripts/install/install.sh | bash
```

:::

这组命令用于首次安装或更新全局 MPE 环境。引导脚本下载并校验安装工具，由 mpelb 安装后端及发布清单指定的 MaaFramework、MaaAgentBinary 和 OCR。仅使用浏览器时无需安装 Desktop 或下载本地 Editor；安装与服务运行互斥，失败时恢复此前环境。

MPE Desktop 会额外安装同版本 Editor。环境中已有 Editor 时，之后从命令行更新环境也会同步更新它，避免桌面前后端版本不一致。

### 强制重装依赖

```bash
mpelb deps reinstall        # 重装全部依赖，与 all 相同
mpelb deps reinstall all
mpelb deps reinstall mfw    # 重装 MaaFramework 与 MaaAgentBinary
mpelb deps reinstall ocr    # 重装原生 OCR 模型
```

重装会重新下载并替换 `mpelb` 所在目录的 `runtime/maafw` 或 `runtime/resource/model/ocr` 中的对应组件，不因版本一致或已有文件而跳过。请先停止使用这些依赖的 LocalBridge 服务。下载、解压和检查通过后才开始替换；网络失败可重新执行命令。

依赖版本由当前 `mpelb` 对应发布清单确定，不会追随最新 release。源码构建的 `dev` 版本请在源码仓库中使用 `yarn update:mfw` 更新开发运行时。

此命令通过 mpelb 内置安装模块下载并校验基础环境包，仅替换指定运行依赖，不更新 `mpelb` 本体、不下载或修改 Editor，也不修改配置文件或 PATH。纯 CLI 环境无需补装 Editor 即可修复依赖。

::: tip
Windows 请优先使用 PowerShell 安装命令，以便自动准备附属运行环境。
:::

修复运行依赖可使用上述 `deps reinstall` 命令；更新整套环境可使用 `env install`，无需手动删除文件。

## 命令格式

```bash
mpelb [command] [args] [flags]
```

- 直接执行 `mpelb` 即可启动本地服务。
- `command` 为子命令，如 `config`、`info`。
- `flags` 为全局或命令级参数。

## 全局参数

| 参数 | 简写 | 说明 | 适用场景 |
|------|------|------|----------|
| `--config` | - | 指定自定义配置文件路径 | 启动、config 子命令 |
| `--root` | - | 临时指定 MaaFramework 项目根目录，用于 PI 发现、资源索引和文件管理 | 启动 |
| `--interface` | - | 指定 Project Interface V2 的 `interface.json` 入口；相对路径以 `--root` 为基准，绝对路径可位于根目录外；为空时自动检索 | 启动 |
| `--port` | - | 指定 WebSocket 服务端口 | 启动 |
| `--log-dir` | - | 指定日志输出目录 | 启动 |
| `--log-level` | - | 指定日志级别：`DEBUG` / `INFO` / `WARN` / `ERROR` | 启动 |
| `--portable` | - | 便携模式：配置与日志存放在可执行文件同目录 | 启动、`config`、`info` |
| `--version` | `-v` | 显示当前版本号 | 任意 |

## 启动服务（根命令）

不加子命令时，`mpelb` 会启动 LocalBridge WebSocket 服务。

### 快速启动

推荐先进入包含 `interface.json`、资源目录和 Agent 目录的 MaaFramework 项目根目录，再直接启动：

```bash
mpelb
```

### 常用启动示例

```bash
# 指定项目根目录
mpelb --root D:/MaaProject

# 指定 Project Interface 入口（相对 --root）
mpelb --root D:/MaaProject --interface ./assets/interface.json

# 指定服务端口
mpelb --port 9999

# 调整日志级别
mpelb --log-level DEBUG

# 便携模式启动
mpelb --portable

# 组合使用
mpelb --root ./MaaProject --port 9066 --log-level INFO --log-dir ./logs
```

::: warning 注意
修改 `--port` 后，需要在编辑器配置面板中同步修改端口号，否则前端无法正常连接。
:::

## 配置管理命令：`mpelb config`

`config` 是一组用于管理 LocalBridge 配置的子命令。

| 命令 | 参数 | 说明 |
|------|------|------|
| `mpelb config open` | - | 使用系统默认编辑器打开配置文件 |
| `mpelb config set-interface [path]` | `path`（可选） | 设置 Project Interface V2 入口；省略路径并直接回车可恢复自动检索 |
| `mpelb config open-log` | - | 使用系统文件管理器打开日志目录 |

### 示例

```bash
# 打开配置文件
mpelb config open

# 交互式设置 PI 入口；直接回车恢复自动检索
mpelb config set-interface

# 直接设置 PI 入口
mpelb config set-interface ./assets/interface.json

# 打开日志目录
mpelb config open-log
```


## 信息查看命令：`mpelb info`

显示 LocalBridge 当前的运行模式、数据目录、配置文件路径、日志目录和可执行文件路径等信息。

```bash
mpelb info
```

在便携模式下查看：

```bash
mpelb info --portable
```

## 运行模式说明

LocalBridge 会根据启动参数和环境自动选择配置存储位置：

| 模式 | 触发条件 | 配置/日志存储位置 |
|------|----------|-------------------|
| 本地模式 | 默认 | 系统用户数据目录 |
| 便携模式 | 使用 `--portable` | 可执行文件同目录 |
| 开发模式 | 可执行文件旁存在 `config/` 目录 | 可执行文件同目录 |

## 常用组合速查

| 用途 | 命令 |
|------|------|
| 默认启动 | `mpelb` |
| 指定项目目录启动 | `mpelb --root ./MaaProject` |
| 指定 PI 入口 | `mpelb --root ./MaaProject --interface ./interface.json` |
| 调试模式启动 | `mpelb --log-level DEBUG` |
| 便携模式启动 | `mpelb --portable` |
| 查看路径信息 | `mpelb info` |
| 打开配置文件 | `mpelb config open` |
| 打开日志目录 | `mpelb config open-log` |
| 查看版本 | `mpelb -v` |

## 桌面与环境管理

```sh
mpelb env check --json
mpelb env install --version latest --json
mpelb env install --version <完整版本号> --json
mpelb env install --with-editor --version latest --json
mpelb env check --with-editor --json
mpelb env recover --json
mpelb service status --json
mpelb service stop --json
mpelb service stop --id <实例ID> --force --json
```

`env check` 默认检查 mpelb 与运行依赖，返回版本、安装路径、就绪状态与缺失项。加上 `--with-editor` 时还会检查 Editor 是否完整且与后端同版本。`env install --with-editor` 用于安装桌面所需的整套环境，MPE Desktop 自动使用此选项；默认安装不会给纯 CLI 环境额外下载 Editor，已有 Editor 则随环境更新。

安装完成后立即切换全局环境；存在未完成安装时先运行 `env recover`。Windows 自更新由临时进程在原进程退出后完成，以输出的 `complete` 事件为完成依据。

`service status` 查询唯一实例的身份、项目目录和状态；`service stop` 请求正常停止。正常停止失败且确认可以中断任务时，可显式提供实例 ID 并使用 `--force`。

查询类命令可以在服务运行时使用。安装、更新与依赖修复需要停止服务。桌面操作方式见 [MPE Desktop](/guide/start/desktop)。
