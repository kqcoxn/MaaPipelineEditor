设备连接是使用 MaaFramework 功能（截图、OCR、调试等）的前提。MPE 通过 LocalBridge 支持多种设备类型，覆盖 Windows、macOS 和 Linux 三大平台。

## 支持的设备类型

不同平台支持的控制器类型如下：

| 平台 | 支持的控制器 |
|------|-------------|
| **Windows** | ADB、Win32、Gamepad |
| **macOS** | ADB、macOS、PlayCover |
| **Linux** | ADB、Linux 统一控制器 |

::: tip
连接面板会根据当前操作系统自动显示可用的设备类型，无需手动筛选。
:::

## 打开连接面板

点击编辑区右上角的连接按钮，展开连接面板。连接面板中可以选择设备类型、配置参数并建立连接。

### 自动连接上次控制器

MPE 默认会记住最近一次成功连接的控制器。LocalBridge 连接成功后，MPE 会自动尝试恢复该控制器，包括 ADB、Win32、PlayCover、Gamepad、Linux 和 macOS 控制器。

该功能默认开启，也可在 **设置 → 本地服务 → 自动连接上次控制器** 中关闭。自动连接期间，右上角设备按钮会显示连接中的加载状态；连接失败时不会重复弹出提示，可打开连接面板查看错误并手动重试。

如果主动点击 **断开连接**，MPE 会清除自动恢复目标，后续启动不会再次连接该控制器。

### 设备列表刷新

首次打开连接面板时，MPE 会自动刷新当前控制器类型的设备列表，即使当前已经连接设备。切换 ADB、Win32 或 Linux 类型后，对应类型的列表会在首次进入时刷新。

自动连接不要求提前打开连接面板；连接成功后，右上角会显示已恢复的设备名称。打开连接面板后，当前类型列表仍会独立刷新。

## ADB（Android 设备）

ADB 是最常用的连接方式，适用于 Android 模拟器和真机。

### 自动扫描

连接面板默认会自动扫描本地 ADB 设备列表，显示已连接的设备供选择。

### 手动连接

若自动扫描未找到设备，可手动输入连接信息：

- **ADB 路径**：ADB 可执行文件路径（留空则使用系统 PATH 中的 adb）
- **设备地址**：设备的 serial 地址（如 `127.0.0.1:5555`、`emulator-5554`）
- **额外配置**：可选 JSON 配置；没有特殊需求时可以留空

### 截图方式

ADB 设备条目会同时记录当前选用的截图方式和 LocalBridge 检测到的可用截图方式。连接设备时应优先从可用方式中选择；设备不支持当前方式时，连接反馈会显示后端返回的警告信息。

| 方式 | 说明 |
|------|------|
| EncodeToFileAndPull | 编码为文件后拉取（兼容性最好） |
| Encode | 直接编码传输 |
| RawWithGzip | 原始数据 + Gzip 压缩 |
| RawByNetcat | 通过 Netcat 传输原始数据 |
| MinicapDirect | Minicap 直连 |
| MinicapStream | Minicap 流式传输 |
| EmulatorExtras | 模拟器专用加速 |

### 输入方式

| 方式 | 说明 |
|------|------|
| AdbShell | ADB Shell 输入（兼容性最好） |
| MinitouchAndAdbKey | Minitouch 触控 + ADB 按键 |
| Maatouch | MaaTouch 输入（推荐） |
| EmulatorExtras | 模拟器专用加速 |

::: tip
大多数情况下使用默认配置即可。若遇到截图黑屏或输入无响应，可尝试切换截图/输入方式。
:::

## Win32（Windows 窗口）

Win32 控制器用于连接 Windows 桌面应用程序窗口。

### 窗口选择

连接面板会列出当前系统中所有可见窗口，选择目标窗口即可连接。列表显示窗口标题和进程名称。

### 配置参数

- **截图方式**：默认 FramePool（帧池截图）
- **鼠标输入方式**：可选择消息输入、驱动输入或 AnchoredTouch 等方式
- **键盘输入方式**：独立于鼠标选择，默认 SendMessage

AnchoredTouch 仅支持点击和滑动，不支持滚轮和键盘。它要求 Windows 10 1809 或更新系统，不移动光标；目标窗口被遮挡时可能短暂闪烁，不能直接操作最小化窗口。需要滚轮时请选择其他鼠标输入方式。

## Gamepad（游戏手柄）

Gamepad 控制器支持通过游戏手柄进行输入操作，仅在 Windows 平台可用。

### 支持的手柄类型

- **Xbox360**：Xbox 360 兼容手柄
- **DualShock4**：PlayStation DualShock 4 手柄

### 配置参数

- **hwnd**：目标窗口句柄
- **截图方式**：与 Win32 相同
- **输入方式**：手柄输入映射

## PlayCover（macOS iOS 模拟）

PlayCover 控制器用于连接 macOS 上通过 PlayCover 运行的 iOS 应用，仅在 macOS 平台可用。

### 配置参数

- **地址（Address）**：PlayCover 连接地址
- **UUID**：应用的唯一标识符
- **名称（Name）**：应用显示名称

## macOS（原生应用）

macOS 控制器用于连接 macOS 原生应用程序，仅在 macOS 平台可用。

### 配置参数

- **窗口 ID**：选择目标应用窗口
- **截图方式**：默认 ScreenCaptureKit
- **输入方式**：GlobalEvent（全局事件）或 PostToPid（发送到进程）

## Linux 统一控制器

Linux 控制器提供以下组合：

- **Wlr 截图或输入**：选择列表中的 Wayland socket，或手动填写路径，例如 `/run/user/1000/wayland-0`。
- **PipeWire 截图**：填写 gamescope 等会话 daemon 提供的节点 ID。此入口使用 daemon 节点直连，不支持桌面 portal 授权捕获，也不能填写其他进程的文件描述符。
- **Libei 输入**：填写 EIS socket 路径，例如 `/run/user/1000/gamescope-0-ei`。
- **UInput 输入**：可指定设备路径及屏幕宽高，设备路径默认 `/dev/uinput`；LocalBridge 需有访问该设备的权限。
- **None 输入**：只截图，不注入输入。

「键盘输入使用 Win32 Virtual Keycode」决定键码是否由框架转换为 Linux evdev 码。未勾选时使用原始 evdev 键码。Wlr 截图与 Libei 输入等组合可按目标合成器能力选择。

## 截图分辨率设置

在「设置 → 本地服务 → 截图分辨率」中选择模式。字段工具与网页调试共用此配置。

| 模式 | 行为 |
| --- | --- |
| 默认 | 短边缩放到 720 |
| 自定义短边 | 短边缩放到指定长度，保持宽高比 |
| 自定义长边 | 长边缩放到指定长度，保持宽高比 |
| Expand 参考分辨率 | 指定参考宽、高，保持宽高比，使输出两边均不小于参考尺寸 |
| 原始分辨率 | 不缩放 |

Expand 使用 `scale = max(参考宽 / 原图宽, 参考高 / 原图高)`，不裁剪、不进行非等比拉伸。例如原图为 2400×1080、参考为 1280×720 时，输出为 1600×720，适合使用 Unity Canvas Scaler Expand 的模板匹配场景。

PI 的显示分辨率字段不会接管实际控制器。请手动将这里的配置与模板、ROI 坐标系保持一致；切换模式后重新截图并核对坐标。

## 连接状态

连接成功后，编辑区右上角的连接按钮会变为蓝色，并显示已连接的设备信息。

连接面板中可以：

- 查看当前连接状态
- 断开当前设备
- 切换到其他设备

::: warning
同一时间只能连接一个设备。切换设备前需要先断开当前连接。
:::

## 常见问题

### ADB 设备列表为空

1. 确认模拟器或设备已启动
2. 确认 ADB 服务正在运行（终端执行 `adb devices` 检查）
3. 若使用自定义 ADB 路径，确认路径正确

### Win32 窗口列表中找不到目标窗口

1. 确认目标应用已启动且窗口可见
2. 部分全屏应用可能不在列表中，尝试切换为窗口模式
3. 刷新窗口列表

### 连接后截图黑屏

1. 尝试切换截图方式（如从 Encode 切换到 EncodeToFileAndPull）
2. 确认设备画面正常显示
3. 部分模拟器需要使用 EmulatorExtras 方式
