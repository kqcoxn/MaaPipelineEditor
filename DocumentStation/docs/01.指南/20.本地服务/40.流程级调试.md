流程级调试可以直接运行 Pipeline，查看节点执行路径、识别截图、动作详情和日志。需要连接 LocalBridge；支持从指定节点重新运行，不支持断点、暂停或单步执行。

## 开始调试

1. 连接 LocalBridge，初始化 MaaFramework，并连接 ADB 设备或 Win32 窗口。
2. 点击全局工具区的调试按钮，打开「调试工作台」。
3. 在「调试配置」中选择资源和控制器，处理顶部准备检查中的错误。
4. 在「中控台」选择入口节点和运行方式，启动调试。
5. 在「节点线」查看执行记录，点击记录加载识别图、截图或动作详情。

## 调试配置

### 资源与设备

资源可以从扫描到的资源包中选择，也可以手动填写路径。路径应指向包含 `pipeline`、`image` 等子目录的资源根目录；多个资源按顺序加载，后加载的同名资源覆盖先加载的资源。

设备在本地服务中连接或切换。请在「设置 → 本地服务」中选择与项目一致的截图模式，避免截图工具与调试的坐标不一致。

准备检查会列出资源加载、流程图和节点映射问题。**错误需处理后才能运行，警告不阻止运行**。点击文件或节点定位问题，修复并保存后点击「重新检查」。资源检查读取磁盘文件，不代表实际识别效果。

### 使用 Project Interface 配置

项目包含 `interface.json` 时，可选择「Project Interface」模式，使用项目定义的控制器、资源和选项。在「PI 任务上下文」中选择具体任务；只调试普通节点时，可选择「仅环境配置」。

推荐在项目根目录启动 LocalBridge。未找到入口或存在多个入口时，可在后端配置面板为当前项目保存入口，或使用启动参数 `--interface <path>`，详见 [进阶配置](/guide/server/advance)。入口按项目根目录独立保存。资源及 PI 引用文件需位于主 `interface.json` 所在目录内。

PI 文件变化后，按提示重新解析配置。没有有效 PI 时，可切换到「手动」模式配置资源和运行时覆盖。

### 自定义识别与动作（Agent）

只有项目使用自定义识别或动作时才需要配置 Agent。

在「调试配置 → 代理（Agent）」中启用所需 Agent，点击「测试连接」。PI 模式可自动启动项目声明的 Agent；开发环境无法使用默认启动命令时，可填写「启动指令覆盖」，不会修改 `interface.json`。

自行启动 Agent 时，在 MPE 中填写相同的标识符或 TCP 端口。例如，入口脚本使用最后一个参数作为标识符时：

```bash
python agent/main.py mpe-agent
```

保持终端运行，在 MPE 中选择「标识符」并填写 `mpe-agent`，然后测试连接。

连接失败时，检查启动命令、标识符或端口、依赖安装情况，以及 Agent 与 MPE 使用的 MaaFramework 版本是否一致。多个 Agent 的同类自定义名称不能重复。勾选「必需」的 Agent 连接失败会阻止运行。

## 选择运行方式

| 方式 | 用途 |
| --- | --- |
| 完整运行 | 从配置入口验证整条流程 |
| 从选中节点运行 | 从当前节点开始，继续执行后续流程 |
| 单节点运行 | 只执行该节点的识别与动作 |
| 仅识别 | 测试 OCR、模板匹配等识别参数，不执行动作 |
| 仅动作 | 跳过识别，直接执行动作，启动前需要确认 |

建议先用「仅识别」调好参数，再用「单节点运行」验证动作，最后运行后续流程。

从节点启动时默认保留画布位置。需要自动定位时，开启「设置 → 组件 → 调试运行时自动居中节点」。

### 临时覆盖参数

在「中控台 → Pipeline Override」中填写 JSON，可临时修改节点参数或后续连接，无需修改源文件。键使用节点的运行时名称：

```json
{
  "节点名称": {
    "roi": [100, 200, 300, 400]
  },
  "另一个节点": {
    "next": ["跳转目标"]
  }
}
```

覆盖仅用于调试；在 PI 模式下，这里填写的配置优先于 PI 中的配置。

## 查看结果与停止

运行时，画布节点会显示执行状态，顶部悬浮条显示当前阶段和耗时。点击状态区打开中控台，展开箭头查看当前候选节点等详情；关闭工作台后仍可点击悬浮条上的「停止」。

「等待下一轮」表示本轮未识别到目标，不等于运行失败；「未观测到识别」也不能直接判定为识别失败。

点击停止后，请等待「正在停止」结束。当前识别、动作或资源准备可能需要时间退出。超过 10 秒仍未结束时，悬浮条会提供恢复入口；任务在实际退出前仍保持停止中。请先保存文件并导出诊断日志，再通过桌面端「环境管理」结束服务，或在运行 LocalBridge 的终端结束并重启服务。运行结束后可继续查看结果：

- **节点线**：按节点查看执行路径，筛选记录并加载图片、动作详情。缺少产物时，检查「调试配置」中的产物策略是否启用了对应类型。
- **调试日志**：查看 `maafw.log`，点击「刷新」读取最新内容，或「打开所在文件夹」查看完整日志。
- **AI 总结**：生成整次运行报告、失败分析或节点解释，也可开启运行结束后自动生成。使用前需[配置 AI 服务](/guide/server/ai)。

## 在 Interface 中运行项目任务

需要按项目提供的任务列表运行时，点击文件标签前的房屋图标进入「Interface」。这里用于运行项目任务，调试工作台用于排查节点问题，两者不能同时运行。

1. 连接 LocalBridge，通过「项目连接配置」选择 PI 入口。
2. 选择控制器和资源。项目有准备步骤时，先在「运行环境选项」中配置，断开设备后点击「准备项目（连接设备前）」，完成后再连接设备。
3. 勾选任务，点击任务名称设置选项，通过上移／下移调整顺序，也可应用项目提供的任务预设。
4. 点击「开始运行」，在右侧查看设备画面、进度和日志。任务失败或手动停止会终止后续任务。

Interface 运行使用磁盘上已保存的资源，请先保存 Pipeline 修改。运行中调整任务和选项只影响下一次运行。普通选项和任务选择会保存在浏览器中，不写回 PI；含非空密码的配置暂不支持运行。

需要结束时点击「停止运行」并等待完成。**关闭网页或断开连接不会停止已开始的任务**，重新连接后可查看当前状态。

## 常见问题

- **缺少资源路径**：选择资源包，或手动添加包含 `pipeline`、`image` 的资源根目录；必要时刷新资源包列表。
- **控制器不可用**：先在本地服务中连接设备，再启动调试。
- **资源检查失败**：根据诊断定位文件，修复并保存后重新检查。
- **识别或动作失败**：结合节点线中的截图、详情与调试日志排查；中段问题可直接从对应节点重新运行。
