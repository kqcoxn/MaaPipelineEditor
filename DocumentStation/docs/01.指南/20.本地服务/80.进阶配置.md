## 使用自定义配置文件

如果需要使用自定义位置的配置文件：

```bash
mpelb --config ./my-config.json
```

::: tip 提示
命令行参数优先级高于配置文件，您可以使用配置文件设置基础配置，再用命令行参数临时覆盖
:::

### 配置文件结构

配置文件使用 JSON 格式：

```json
{
  "server": {
    "port": 9066,
    "host": "localhost"
  },
  "file": {
    "exclude": ["node_modules", ".git", "dist", "build"],
    "extensions": [".json", ".jsonc"],
    "max_depth": 10,
    "max_files": 10000
  },
  "log": {
    "level": "INFO",
    "dir": "./logs",
    "push_to_client": false
  },
  "maafw": {
    "enabled": false,
    "lib_dir": "",
    "resource_dir": ""
  },
  "interface": {
    "path": ""
  }
}
```

### 配置项说明

- **server.port**: WebSocket 服务端口
- **server.host**: 监听地址（一般保持 localhost）
- **file.root**: 可选的文件扫描根目录。推荐设置为包含 `interface.json`、资源目录和 Agent 目录的 MaaFramework 项目根目录；留空或省略时使用 LocalBridge 的启动工作目录
- **file.exclude**: 排除的目录列表
- **file.extensions**: 扫描的文件后缀
- **file.max_depth**: 最大扫描深度，默认为 10；设为 0 表示不限制深度
- **file.max_files**: 最大索引文件数，默认为 10000；设为 0 表示不限制数量
- **log.level**: 日志级别（DEBUG/INFO/WARN/ERROR）
- **log.push_to_client**: 是否推送日志到前端（一般关闭）
- **maafw.enabled**: 是否启用 MaaFramework 功能
- **maafw.lib_dir**: MaaFramework 库目录路径；为空或路径失效时，会尝试使用 `mpelb` 同目录下的 `runtime/maafw/bin`
- **maafw.resource_dir**: OCR 资源目录路径（`model/` 所在目录）；为空或路径失效时，会尝试使用 `mpelb` 同目录下的 `runtime/resource`
- **interface.path**: Project Interface V2 入口路径。留空时按文件扫描配置在 `file.root` 内检索 `interface.json`；相对路径以 `file.root` 为基准解析；绝对路径可以位于 `file.root` 外。

::: tip 推荐配置
将 `file.root` 设为 MaaFramework 项目根目录，不要设为单个资源路径或 `pipeline` 目录。项目根目录可以同时覆盖 PI 自动发现、资源索引、文件管理和 Agent 启动所需的项目结构。
:::

### 文件根目录优先级

LocalBridge 按以下顺序确定文件根目录：

1. 启动参数 `--root <目录>`
2. 配置文件中的 `file.root`
3. 启动 LocalBridge 时的进程工作目录

`--root` 中的相对路径以进程工作目录为基准；`file.root` 中的相对路径以配置文件所在目录为基准。空字符串、`.` 和 `./` 均视为未配置。命令行参数只在当前进程生效，不会因保存其他配置项而写入配置文件。

显式选择的根目录不存在、不可访问或不是目录时，LocalBridge 会停止启动并报告对应来源，不会静默改用工作目录。

### Project Interface 入口优先级

LocalBridge 按以下顺序确定 `interface.json`：

1. 启动参数 `--interface <path>`
2. 配置文件 `interface.path`
3. 自动检索根目录下的 `interface.json`

自动检索找到零个文件时不启用 PI；找到一个文件时自动加载；找到多个文件时保留候选列表并提示显式指定入口。显式路径无效时不会回退自动检索。

自动检索遵循 `file.exclude`、`file.max_depth` 和 `file.max_files`。位于排除目录、扫描深度之外，或在达到文件数量上限后才出现的 `interface.json` 不会成为自动检索候选。

显式入口可以位于文件根目录外。PI 的 `import`、语言文件、`resource.path` 和 `controller.attach_resource_path` 仍以主 `interface.json` 所在目录为范围解析，不能越出该目录。LocalBridge 会监听这些来源文件并在内容变化后刷新 PI 状态。显式入口不会扩大文件索引范围，文件面板仍只显示 `file.root` 内的 Pipeline 文件。

可以使用配置命令修改入口：

```bash
# 交互式输入路径；直接回车表示恢复自动检索
mpelb config set-interface

# 直接指定路径
mpelb config set-interface ./assets/interface.json
```

命令行参数只对当前进程生效，不会写入配置文件：

```bash
mpelb --root D:/MaaProject --interface ./assets/interface.json
```

### MaaFramework 默认路径

通过一键安装脚本部署时，LocalBridge 会在 `mpelb` 可执行文件同目录准备附属运行环境：

```text
runtime/
├── maafw/
│   └── bin/
└── resource/
    └── model/
        └── ocr/
```

运行时路径优先级如下：

1. `maafw.lib_dir` / `maafw.resource_dir` 指向的路径存在时，优先使用配置文件中的路径
2. 配置为空或路径不存在时，自动使用 `mpelb` 同目录下的 `runtime/maafw/bin` 与 `runtime/resource`
3. 两者都不可用时，相关 MaaFramework 或原生 OCR 功能不可用，并在日志中给出提示

::: tip
默认路径只在运行时解析，不会自动写入 `config.json`。因此，安装脚本不会覆盖您手动配置过的 MaaFramework 或 OCR 路径。
:::

## 配置存储位置

LocalBridge 支持三种运行模式，会自动选择合适的配置存储位置：

### 本地模式（默认）

配置文件存储在系统用户数据目录：

- **Windows**: `%APPDATA%\MaaPipelineEditor\LocalBridge\config.json`
- **macOS**: `~/Library/Application Support/MaaPipelineEditor/LocalBridge/config.json`
- **Linux**: `~/.config/MaaPipelineEditor/LocalBridge/config.json`

日志文件同样存储在该目录下的 `logs` 子目录。

### 便携模式

如果需要将配置与可执行文件放在一起（例如使用 U 盘携带），可以使用 `--portable` 参数：

```bash
mpelb --portable
```

此模式下，配置和日志都存储在可执行文件同目录。

### 开发模式

如果在可执行文件旁检测到 `config` 目录，会自动进入开发模式，使用该目录下的配置文件。

## 查看日志

LocalBridge 的日志会输出到三个位置：

1. **终端控制台**：实时查看运行状态
2. **前端日志窗口**：在编辑器界面中快捷查看后端日志
3. **日志文件**：保存在数据目录下的 `logs/lb-YYYY-MM-DD.log`

### 日志文件位置

日志文件位置取决于运行模式：

- **本地模式**：
  - Windows: `%APPDATA%\MaaPipelineEditor\LocalBridge\logs\`
  - macOS: `~/Library/Application Support/MaaPipelineEditor/LocalBridge/logs/`
  - Linux: `~/.config/MaaPipelineEditor/LocalBridge/logs/`
- **便携模式**：可执行文件同目录下的 `logs/`
- **开发模式**：可执行文件同目录下的 `logs/`

日志格式：`[时间戳][级别][模块] 消息内容`

### 快速打开日志文件夹

您可以使用以下命令快速打开日志文件所在目录：

```bash
mpelb config open-log
```

该命令会使用系统默认文件管理器打开日志目录，方便您查看和管理日志文件。

您也可以使用 `mpelb info` 命令查看当前的日志目录路径。
