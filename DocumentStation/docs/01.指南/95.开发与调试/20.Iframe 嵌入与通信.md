本文档面向需要在自身应用中嵌入 MaaPipelineEditor（下称 MPE）的开发者。MPE 通过 iframe 嵌入模式，使宿主应用（如 VSCode 插件、Web IDE 等）可以在不依赖 LocalBridge 后端服务的情况下，将流程编辑器集成到自有的界面中。

## 概述

在嵌入模式下，MPE 以 iframe 为容器运行，宿主与 MPE 之间通过 `window.postMessage` 进行双向通信。嵌入模式不连接任何后端服务，文档同步和持久化由宿主代理完成。

| 维度     | 嵌入模式      | 在线/独立模式 |
| -------- | ------------- | ------------- |
| 通信方式 | `postMessage` | WebSocket     |
| 后端依赖 | 无            | LocalBridge   |
| 文件访问 | 宿主代理      | LB 文件服务   |
| 设备连接 | 不提供        | 通过 LB       |
| 调试功能 | 不提供        | 通过 LB       |
| UI 定制  | 宿主可配置    | 不可配置      |

## 激活方式

在 iframe 的 `src` 中添加 URL 参数即可激活嵌入模式：

```
https://mpe.codax.site/stable/?embed=true&origin=vscode-maa
```

| 参数     | 必填 | 说明                                       |
| -------- | ---- | ------------------------------------------ |
| `embed`  | 是   | 设为 `true` 激活嵌入模式                   |
| `origin` | 否   | 声明宿主来源，用于调试与可选的 origin 校验 |

::: tip `origin` 参数说明
`origin` 的值可以是两种形式：

- **标识符**（如 `vscode-maa`、`test-host`）：仅用于日志记录和调试，不做严格的 postMessage origin 校验
- **完整 URL**（如 `https://my-app.com`）：MPE 会对收到的 postMessage 消息做严格的 `event.origin` 匹配，不匹配的消息会被丢弃

如果 `origin` 以 `http` 开头，MPE 会启用严格的 origin 校验；否则仅作为标识符使用。
:::

## 消息格式

所有 postMessage 消息使用统一的信封格式：

```typescript
interface EmbedMessage {
  protocol: "mpe-embed"; // 协议标识，防止消息串扰
  version: string; // 协议版本，如 "1.4.0"
  type: string; // 消息类型
  requestId?: string; // 请求 ID，用于请求-响应模式匹配
  payload: any; // 消息体
}
```

MPE 仅处理 `protocol` 为 `"mpe-embed"` 的消息，其余 postMessage 消息会被静默忽略。

嵌入模式下，MPE 的日志面板会显示“嵌入通信”页签，记录通过来源校验的接收消息和 MPE 发出的消息。记录包含方向、消息类型、时间、`requestId`、origin 和 payload，最多保留最近 200 条，可在页签内手动清空。

## 握手流程

iframe 加载完成后，宿主需主动发起握手：

```
宿主                              MPE (iframe)
  │                                  │
  │  ─── mpe:init ──────────────►    │
  │      { capabilities, ui, host }  │
  │                                  │
  │  ◄──── mpe:ready ─────────────   │
  │      { version, supportedCaps }  │
  │                                  │
  │    (握手完成，正式通信)           │
```

1. iframe 加载完成后，宿主发送 `mpe:init`，携带[权限声明](#能力声明)与[UI 配置](#ui-控制)
2. MPE 根据声明配置自身，回复 `mpe:ready`
3. **握手完成前，MPE 忽略所有非 `mpe:init` 消息**
4. 若 **5 秒**内未收到 `mpe:init`，MPE 会使用[默认权限集](#默认权限集)自动完成握手并继续运行

::: warning 注意
`mpe:init` 消息中的 `requestId` 必须原样回填到 `mpe:ready` 中，否则宿主的请求会超时。建议宿主侧设置 **10 秒**超时。
:::

## 宿主 → MPE 消息

| 类型               | 说明                      | payload                | 响应              |
| ------------------ | ------------------------- | ---------------------- | ----------------- |
| `mpe:init`         | 握手 + 权限/UI 声明       | `EmbedInitConfig`      | `mpe:ready`       |
| `mpe:loadPipeline` | 加载 pipeline JSON 数据   | `{ fileName?, data, anchorDefinitions? }` | `mpe:loadResult`  |
| `mpe:navigateNodeResult` | 返回宿主节点导航结果 | `{ success, nodeName, message? }` | — |
| `mpe:save`         | 请求 MPE 回传当前流程数据 | `{}`                   | `mpe:saveData`    |
| `mpe:saveResult`   | 返回宿主写回结果          | `{ success, ... }`     | —                 |
| `mpe:selectNode`   | 选中指定节点              | `{ nodeId }`           | —                 |
| `mpe:focusNode`    | 聚焦并视口定位到指定节点  | `{ nodeId }`           | —                 |
| `mpe:resize`       | 通知 iframe 容器尺寸变化  | `{ width, height }`    | —                 |
| `mpe:state`        | 查询 MPE 当前状态         | `{ fields: string[] }` | `mpe:stateResult` |
| `mpe:destroy`      | 通知 MPE 清理嵌入资源     | `{}`                   | —                 |

### 加载流程数据

`mpe:loadPipeline` 的 `data` 字段为标准 MaaFramework pipeline JSON 对象。MPE 收到后会调用内部解析器将其转换为流程图渲染。

```typescript
{
  type: "mpe:loadPipeline",
  requestId: "uuid",
  payload: {
    fileName: "pipeline.json",  // 可选，用于 saveData 回填
    data: { /* Pipeline JSON */ },
    anchorDefinitions: [
      {
        anchorName: "LoginState",
        nodeName: "CheckLogin",
        fileName: "login.json",
        relativePath: "pipeline/login.json",
        isCurrentFile: false
      }
    ]
  }
}
```

`anchorDefinitions` 用于补充当前资源中定义 Anchor 的 Pipeline 节点。MPE 在 iframe 中始终使用当前画布的 `anchorReferenceIndex` 作为当前文件实时结果，只合并 `isCurrentFile === false` 的宿主结果；宿主提供的当前文件快照不会覆盖尚未保存的画布状态。结果按文件与节点去重，列表仅供查看，不触发本地或宿主导航。

MPE 响应 `mpe:loadResult`：

```typescript
{
  type: "mpe:loadResult",
  requestId: "uuid",  // 与请求相同的 requestId
  payload: {
    success: true,
    fileName: "pipeline.json"
  }
}
```

### 保存流程数据

宿主发送 `mpe:save` 后，MPE 将当前流程图序列化为 pipeline JSON 并回传：

```typescript
{
  type: "mpe:saveData",
  requestId: "uuid",
  payload: {
    fileName: "pipeline.json",
    data: { /* Pipeline JSON */ }
  }
}
```

当保存由 MPE 内的“保存到宿主”按钮或 `Ctrl/Cmd+S` 发起时，宿主应复用 `mpe:saveRequest` 的 `requestId` 发送 `mpe:save`。收到 `mpe:saveData` 并完成实际写回后，再使用相同 `requestId` 发送保存结果：

```typescript
{
  type: "mpe:saveResult",
  requestId: "save-uuid",
  payload: {
    success: true,
    documentVersion: 42 // 可选，宿主文档版本
  }
}
```

失败时 `success` 为 `false`，宿主应通过结构化 `code` 表达错误类型；`message` 只作为未知客户端或日志的回退信息。MPE 只在成功结果到达后更新 clean 基线；若保存期间又发生编辑，较新的改动仍保持未保存状态。

宿主发现数据源在 MPE 最近一次加载或同步后发生变化时，可以返回通用文档冲突：

```typescript
{
  protocol: "mpe-embed",
  version: "1.4.0",
  type: "mpe:saveResult",
  requestId: "save-uuid",
  payload: {
    success: false,
    code: "document_changed",
    message: "The host document has changed",
    canForce: true
  }
}
```

MPE 仅根据 `code: "document_changed"` 进入冲突确认，不解析 `message`。用户可以从宿主重新同步、取消，或在 `canForce === true` 时明确授权覆盖。取消会保留当前 Pipeline 和 dirty 状态，且不会发送新请求。

### 节点选中与聚焦

`mpe:selectNode` 和 `mpe:focusNode` 都通过 `nodeId` 定位节点。MPE 的实现支持两种查找方式：

1. **按节点内部 ID**（ReactFlow 的 `node.id`）精确匹配
2. **按节点标签回退**（`node.data.label`，即节点显示名称）——当按 ID 找不到时自动尝试按标签匹配

如果两种方式都找不到节点，MPE 会发送 `mpe:error`：

```typescript
{
  type: "mpe:error",
  payload: {
    code: "node_not_found",
    message: "Node not found: 节点名称"
  }
}
```

`mpe:focusNode` 定位成功后，MPE 会调用 `fitView` 将视口平滑移动到目标节点（动画时长 300ms）。

### 容器尺寸与销毁

宿主调整 iframe 容器尺寸后，可发送 `mpe:resize`，通知 MPE 重新计算依赖视口尺寸的界面元素。`width` 和 `height` 用于描述宿主完成调整后的尺寸；iframe 元素本身的尺寸仍由宿主负责设置。

宿主准备移除 iframe 时可先发送 `mpe:destroy`。MPE 收到后会注销消息、快捷键等嵌入模式监听器并重置嵌入状态；该消息不返回响应，宿主仍负责最终移除 iframe。

### 状态查询

`mpe:state` 通过 `fields` 数组查询 MPE 的当前状态。目前支持的字段：

| 字段         | 类型             | 说明                       |
| ------------ | ---------------- | -------------------------- |
| `version`    | `string`         | 嵌入协议版本，如 `"1.4.0"` |
| `nodesCount` | `number`         | 当前节点数量               |
| `edgesCount` | `number`         | 当前边数量                 |
| `fileName`   | `string \| null` | 当前文件名                 |
| `readOnly`   | `boolean`        | 是否处于只读模式           |

## MPE → 宿主消息

| 类型                      | 说明                          | payload                          |
| ------------------------- | ----------------------------- | -------------------------------- |
| `mpe:ready`               | 初始化完成，握手响应          | `{ version, supportedCaps }`     |
| `mpe:loadResult`          | 加载结果                      | `{ success, fileName?, error? }` |
| `mpe:saveData`            | 回传流程数据                  | `{ fileName, data }`             |
| `mpe:change`              | 流程图变更通知                | `{ type, detail }`               |
| `mpe:nodeSelect`          | 用户选中节点                  | `{ nodeId, nodeData? }`          |
| `mpe:saveRequest`         | MPE 主动请求保存（如 Ctrl+S） | `{ hint, force }`                |
| `mpe:reloadRequest`       | MPE 请求重新加载宿主文档      | `{}`                             |
| `mpe:openExternalRequest` | MPE 请求宿主打开外部链接      | `{ url }`                        |
| `mpe:navigateNodeRequest` | MPE 请求宿主定位 External 目标节点 | `{ nodeName }`               |
| `mpe:stateResult`         | 状态查询结果                  | `{ [field]: value }`             |
| `mpe:error`               | 错误通知                      | `{ code, message, detail? }`     |

### 变更通知

MPE 在 Pipeline 导出结果相对 clean 基线发生变化时，会向宿主推送 `mpe:change` 消息：

| type              | 说明                  | detail                              |
| ----------------- | --------------------- | ----------------------------------- |
| `pipeline.update` | Pipeline 导出结果变化 | `{ nodeCount, edgeCount, isDirty }` |

::: warning
变更通知为**尽力交付**（best-effort），不做消息确认，宿主不应依赖其做精确的状态同步。需要精确状态时应使用 `mpe:save` 获取全量数据。

变更通知内置 **300ms 防抖**：在防抖窗口内发生多次变更时，仅发送最后一次的通知（detail 取最终值）。
:::

### 保存请求

当用户点击嵌入态保存按钮，或按下 `Ctrl+S`（或 `Cmd+S`）时，MPE 会发送 `mpe:saveRequest` 通知宿主：

```typescript
{
  type: "mpe:saveRequest",
  requestId: "save-uuid",
  payload: { hint: "user-triggered", force: false }
}
```

宿主收到后执行 `mpe:save` → `mpe:saveData` → 实际写回 → `mpe:saveResult` 完整流程。MPE 对保存请求设置 10 秒超时；失败或超时不会清除 dirty 状态。

用户在 `document_changed` 冲突 UI 中选择“强制覆盖”后，MPE 使用新的 `requestId` 发送：

```typescript
{
  type: "mpe:saveRequest",
  requestId: "save-force-uuid",
  payload: { hint: "user-confirmed-force", force: true }
}
```

`force: true` 仅表示用户已经明确授权使用 MPE 当前完整数据覆盖宿主侧当前数据，不指向磁盘、编辑器文档或任何特定存储介质。实际写回方式仍由宿主决定，宿主也可以因权限、资源失效或其他原因拒绝保存。`canForce` 表示宿主当前允许 MPE 向用户提供此操作。

### 重新同步宿主文档

用户点击“从宿主同步”时，MPE 发送：

```typescript
{
  type: "mpe:reloadRequest",
  requestId: "reload-uuid",
  payload: {}
}
```

宿主应重新读取当前绑定文档，而不是使用打开 iframe 时缓存的数据。解析成功后，使用相同 `requestId` 发送 `mpe:loadPipeline`；MPE 通过 `mpe:loadResult` 返回加载结果。读取或解析失败时，宿主发送相同 `requestId` 的 `mpe:error`。

MPE 存在未保存修改时会先请求用户确认。只有 `mpe:loadResult.success` 为 `true` 时才替换 clean 基线并清除 dirty；失败时保留当前画布。

### 打开外部链接

iframe 中的浏览器弹窗可能被 Webview 或宿主安全策略拦截。用户触发文档、仓库等外部链接时，MPE 不直接依赖 `window.open`，而是发送：

```typescript
{
  type: "mpe:openExternalRequest",
  payload: { url: "https://mpe.codax.site/docs/" }
}
```

宿主必须重新解析并校验 URL，仅允许 `http:` / `https:` 等明确批准的协议，再通过宿主环境的安全外链 API 打开。VS Code 扩展应调用 `vscode.env.openExternal(vscode.Uri.parse(url))`，不要把未经校验的 URL 拼接到命令 URI、HTML 或 shell 命令中。

### External 节点导航

宿主声明 `hostNodeNavigation: true` 后，用户在 iframe 中触发 External 节点导航时，MPE 直接发送请求：

```typescript
{
  protocol: "mpe-embed",
  version: "1.4.0",
  type: "mpe:navigateNodeRequest",
  requestId: "navigate-node-uuid",
  payload: { nodeName: "Shared_Login" }
}
```

宿主完成节点查找、文件切换和定位后，必须使用相同 `requestId` 返回：

```typescript
{
  protocol: "mpe-embed",
  version: "1.4.0",
  type: "mpe:navigateNodeResult",
  requestId: "navigate-node-uuid",
  payload: {
    success: true,
    nodeName: "Shared_Login",
    message: "已在 pipeline/login.json 中定位 Shared_Login"
  }
}
```

MPE 只接受匹配 `requestId` 的结果，并设置 10 秒超时。协议销毁时会取消所有待处理导航。iframe 路径不会先搜索当前 Tab、连接或查询 LocalBridge，也不会在宿主失败后回退到本地跨文件逻辑。未声明 `hostNodeNavigation` 时能力按 `false` 处理，MPE 不发送请求并禁用 External 跳转入口。

Anchor 节点不使用此请求：iframe 中字段工具栏不提供 Anchor 跳转，Anchor 定义弹层保留但列表项只读。独立模式仍沿用 MPE 多 Tab / LocalBridge 的 External 与 Anchor 跨文件行为。

## 能力声明

宿主在 `mpe:init` 中通过 `capabilities` 字段声明期望的能力集合，MPE 会据此限制对应功能：

```typescript
interface EmbedCapabilities {
  readOnly: boolean; // 只读模式，禁止编辑流程图
  allowCopy: boolean; // 允许复制/粘贴节点
  allowUndoRedo: boolean; // 允许撤销/重做
  allowAutoLayout: boolean; // 允许自动布局
  allowSearch: boolean; // 允许搜索面板
  allowCustomTemplate: boolean; // 允许自定义模板
  hostNodeNavigation: boolean; // 允许把 External 节点导航委托给宿主
}
```

各能力的作用范围：

| 能力                  | 生效方式                                                                              |
| --------------------- | ------------------------------------------------------------------------------------- |
| `readOnly`            | 禁用节点拖拽、连接、双击创建、右键菜单；过滤掉所有 remove/add/position 类型的节点变更 |
| `allowCopy`           | 控制 `Ctrl+C` / `Ctrl+V` 是否可用                                                     |
| `allowUndoRedo`       | 控制撤销/重做快捷键                                                                   |
| `allowAutoLayout`     | 控制自动布局按钮是否可用，不可用时点击会触发 `mpe:error`（`capability_denied`）       |
| `allowSearch`         | 控制搜索面板是否显示                                                                  |
| `allowCustomTemplate` | 控制自定义模板面板是否显示                                                            |
| `hostNodeNavigation`  | 控制 iframe External 节点是否可请求宿主导航；未声明时不发送请求                     |

### 默认权限集

若宿主未在 5 秒内发送 `mpe:init`，MPE 使用以下默认值自动完成握手：

| 能力                  | 默认值  |
| --------------------- | ------- |
| `readOnly`            | `false` |
| `allowCopy`           | `true`  |
| `allowUndoRedo`       | `true`  |
| `allowAutoLayout`     | `true`  |
| `allowSearch`         | `true`  |
| `allowCustomTemplate` | `true`  |
| `hostNodeNavigation`  | `false` |

默认集偏保守，仅开放核心编辑能力，关闭需要外部依赖（如 AI 服务）的功能。

## UI 控制

宿主在 `mpe:init` 中通过 `ui` 字段控制 MPE 的界面元素：

```typescript
interface EmbedUIConfig {
  hideHeader: boolean; // 隐藏顶部导航栏
  hideToolbar: boolean; // 隐藏左侧工具栏

```

### 可隐藏的面板 ID

| 面板 ID               | 说明         |

顶部导航栏的本地服务连接按钮在嵌入模式下会始终显示为 **"EmbedBridge"**。点击后会优先提示用户留在宿主应用使用对应能力，并提供 MPE 快速开始文档入口。
:::

## 完整的 EmbedInitConfig

```typescript
interface EmbedInitConfig {
  capabilities: EmbedCapabilities;
  ui: EmbedUIConfig;
  host?: {
    id?: string;
    name?: string;
    repositoryUrl?: string; // 仅接受 HTTPS
  };
}
```

`host` 描述嵌入 MPE 的宿主。界面显示名称优先使用去除首尾空白后的 `host.name`，缺失时按界面语言回退为“宿主”或“Host”。`host.id` 仅用于识别和纯展示优化，不得参与保存、同步或冲突状态机判断。

## 嵌入态界面行为

- 保留 Header；所有宿主使用相同的保存、同步与冲突流程，按钮中的宿主名称来自 `host.name`。
- 所有 iframe 宿主下隐藏本地文件入口和文件 Tab 新增按钮，Header 版本号不提供下拉版本切换。
- 常规导出菜单替换为单一“保存到宿主”，持久化目标始终由宿主决定。
- 跳过使用协议确认、答题/新手引导和更新日志自动弹窗，握手和首次 Pipeline 加载完成后直接可用。
- 小工具、调试和 LocalBridge 入口保留；触发时推荐留在宿主应用使用对应能力，并提供 MPE 快速开始文档入口。
- 宿主身份不会改变协议状态机；持久化目标和写回方式始终由宿主决定。
- External 节点仅在宿主声明 `hostNodeNavigation` 时委托宿主导航；Anchor 不导航，但继续显示当前文件实时定义与宿主提供的跨文件定义。

## 生命周期

```
宿主创建 iframe
      │
      ▼
MPE 加载，检测 embed=true
      │
      ▼
MPE 进入嵌入模式，等待 mpe:init
      │
      ├──── 超时 5s ──► 使用默认权限集自动完成握手
      │
      ▼
收到 mpe:init，配置权限与 UI
      │
      ▼
回复 mpe:ready，握手完成
      │
      ▼
正常通信（loadPipeline / change / save ...）
      │
      ▼
宿主发送 mpe:destroy（可选）
      │
      ▼
MPE 清理资源
      │
      ▼
宿主销毁 iframe
```

## 安全考量

### Origin 校验

MPE 在接收 postMessage 时按以下规则校验：

1. 所有消息必须携带 `protocol: "mpe-embed"`
2. 仅接收来自 `window.parent` 的消息
3. 若 URL `origin` 参数以 `http` 开头，则要求 `event.origin` 严格匹配，并将其作为向宿主发送消息时的 `targetOrigin`
4. 若 `origin` 参数为标识符形式（如 `vscode-maa`），仅用于标识宿主，发送时回退为 `*`

### 版本协商

握手时 MPE 在 `mpe:ready` 中声明自身支持的协议版本（当前为 `1.4.0`）。版本策略遵循语义化版本：

- **主版本号**变更：不兼容的协议变更（消息格式、握手流程等）
- **次版本号**变更：向后兼容的功能新增（新增消息类型、新增 capability 字段）
- **修订号**变更：向后兼容的问题修正

## 宿主侧集成示例

以下是一个完整的宿主侧集成示例，展示了 iframe 创建、握手、消息收发、保存代理的完整流程：

```html
<!DOCTYPE html>
<html>
  <head>
    <meta charset="UTF-8" />
    <title>MPE 嵌入示例</title>
    <style>
      body {
        margin: 0;
        height: 100vh;
        display: flex;
      }
      #mpe-frame {
        flex: 1;
        border: none;
      }
    </style>
  </head>
  <body>
    <iframe
      id="mpe-frame"
      src="https://mpe.codax.site/stable/?embed=true&origin=my-app"
    ></iframe>

    <script>
      const iframe = document.getElementById("mpe-frame");
      const pendingRequests = new Map();
      let requestIdCounter = 0;

      // 发送消息，支持请求-响应模式
      function sendMessage(
        type,
        payload,
        needResponse = false,
        existingRequestId,
      ) {
        const requestId =
          existingRequestId ??
          (needResponse ? `req-${++requestIdCounter}` : undefined);
        const msg = {
          protocol: "mpe-embed",
          version: "1.4.0",
          type,
          ...(requestId ? { requestId } : {}),
          payload,
        };

        iframe.contentWindow.postMessage(msg, new URL(iframe.src).origin);

        if (needResponse) {
          return new Promise((resolve, reject) => {
            pendingRequests.set(requestId, { resolve, reject });
            setTimeout(() => {
              if (pendingRequests.has(requestId)) {
                pendingRequests.delete(requestId);
                reject(new Error(`Request ${type} timeout`));
              }
            }, 10000);
          });
        }
      }

      // 监听 MPE 消息
      window.addEventListener("message", (event) => {
        const data = event.data;
        if (
          !data ||
          data.protocol !== "mpe-embed" ||
          event.source !== iframe.contentWindow
        )
          return;

        // 处理请求-响应匹配
        if (data.requestId && pendingRequests.has(data.requestId)) {
          const { resolve } = pendingRequests.get(data.requestId);
          pendingRequests.delete(data.requestId);
          resolve(data.payload);
          return;
        }

        switch (data.type) {
          case "mpe:ready":
            console.log("MPE ready, version:", data.payload.version);
            console.log("Supported capabilities:", data.payload.supportedCaps);
            break;

          case "mpe:change":
            console.log(
              "Pipeline changed:",
              data.payload.type,
              data.payload.detail,
            );
            // 可在此处实现"未保存"标记
            break;

          case "mpe:saveRequest":
            console.log("MPE requests save:", data.payload);
            // 触发保存流程
            triggerSave(data.requestId, data.payload);
            break;

          case "mpe:reloadRequest":
            reloadFromHost(data.requestId);
            break;

          case "mpe:openExternalRequest": {
            const url = new URL(data.payload.url);
            if (url.protocol === "http:" || url.protocol === "https:") {
              window.open(url.toString(), "_blank", "noopener,noreferrer");
            }
            break;
          }

          case "mpe:navigateNodeRequest":
            navigateNodeInHost(data.requestId, data.payload.nodeName);
            break;

          case "mpe:saveData":
            console.log("Received pipeline data for:", data.payload.fileName);
            // 将 data.payload.data 写入文件系统
            break;

          case "mpe:error":
            console.error(
              "MPE error:",
              data.payload.code,
              data.payload.message,
            );
            break;
        }
      });

      // iframe 加载完成后发起握手
      iframe.addEventListener("load", () => {
        setTimeout(async () => {
          try {
            const result = await sendMessage(
              "mpe:init",
              {
                capabilities: {
                  readOnly: false,
                  allowCopy: true,
                  allowUndoRedo: true,
                  allowAutoLayout: true,
                  allowSearch: true,
                  allowCustomTemplate: false,
                  hostNodeNavigation: true,
                },
                ui: {
                  hideHeader: false,
                  hideToolbar: false,
                  hiddenPanels: [
                    "config",
                    "local-file",
                    "logger",
                    "exploration",
                  ],
                },
                host: {
                  id: "custom-editor",
                  name: "Custom Editor",
                },
              },
              true,
            );
            console.log("Handshake success:", result);
          } catch (err) {
            console.error("Handshake failed:", err);
          }
        }, 500);
      });

      // 加载 pipeline
      async function loadPipeline(fileName, pipelineData, anchorDefinitions) {
        const result = await sendMessage(
          "mpe:loadPipeline",
          {
            fileName,
            data: pipelineData,
            anchorDefinitions,
          },
          true,
        );
        console.log("Load result:", result);
      }

      async function navigateNodeInHost(requestId, nodeName) {
        // 替换为宿主自己的跨文件查找、文件打开与节点定位逻辑。
        const success = false;
        sendMessage(
          "mpe:navigateNodeResult",
          {
            success,
            nodeName,
            message: success ? `已定位 ${nodeName}` : `未找到节点: ${nodeName}`,
          },
          false,
          requestId,
        );
      }

      // 保存 pipeline
      async function triggerSave(requestId, { force }) {
        try {
          const data = await sendMessage("mpe:save", {}, true, requestId);
          console.log("Save data received:", data);
          // 宿主自行决定写回目标，并根据 force 选择是否接受覆盖。
          // await writePipelineToHost(data.payload.data, { force });
          sendMessage("mpe:saveResult", { success: true }, false, requestId);
        } catch (error) {
          sendMessage(
            "mpe:saveResult",
            {
              success: false,
              code: "save_failed",
              message: String(error),
            },
            false,
            requestId,
          );
        }
      }

      async function reloadFromHost(requestId) {
        try {
          // const { fileName, data } = await readCurrentTextDocument();
          const fileName = "pipeline.json";
          const data = {};
          await sendMessage(
            "mpe:loadPipeline",
            { fileName, data },
            true,
            requestId,
          );
        } catch (error) {
          sendMessage(
            "mpe:error",
            { code: "reload_failed", message: String(error) },
            false,
            requestId,
          );
        }
      }

      // 选中节点
      function selectNode(nodeId) {
        sendMessage("mpe:selectNode", { nodeId });
      }

      // 聚焦节点
      function focusNode(nodeId) {
        sendMessage("mpe:focusNode", { nodeId });
      }
    </script>
  </body>
</html>
```

## VSCode WebView 桥接

VSCode WebView 的 `vscode.postMessage` 与 iframe 内的 `window.parent.postMessage` 需要一层中继。宿主需在 WebView 的 HTML 中（iframe 外层）注入中继脚本：

```html
<script>
  const vscode = acquireVsCodeApi();
  // iframe → 扩展进程
  window.addEventListener("message", (event) => {
    if (event.data?.protocol === "mpe-embed") {
      vscode.postMessage(event.data);
    }
  });
</script>
<iframe id="mpe-frame" src="...?embed=true&origin=vscode-maa"></iframe>
```

扩展进程中收到消息后，通过 iframe 的 `contentWindow.postMessage` 转发给 MPE：

```typescript
// 扩展进程 → iframe
panel.webview.onDidReceiveMessage((msg) => {
  const iframe = document.getElementById("mpe-frame");
  iframe.contentWindow.postMessage(msg, "*");
});
```

MPE 侧代码完全不受影响，使用标准的 `window.parent.postMessage` 即可。

## 测试环境

项目源码的 `/Iframe` 目录下提供了一个完整的测试父级环境（`index.html` + `test-host.js` + `test-host.css`），可用于本地验证通信协议的所有消息类型。该测试环境独立于主项目技术栈，直接用浏览器打开即可使用。

测试环境提供了：

- 能力开关（复选框形式配置 capabilities）
- UI 配置（面板隐藏选项）
- 所有消息类型的发送按钮
- Pipeline JSON 输入区
- 实时消息日志（按方向着色：接收为绿色，发送为蓝色，错误为红色）
- 请求-响应超时提示

::: tip
测试环境不依赖任何构建工具，直接将 `dist/` 构建产物与 `Iframe/` 目录部署到同一静态服务器即可测试。
:::
