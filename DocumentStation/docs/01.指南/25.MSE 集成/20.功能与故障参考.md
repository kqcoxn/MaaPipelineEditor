## Pipeline 语言服务

MSE 的语言服务继续作用于 VS Code 中的原始 Pipeline 文本；MPE 负责图形化编辑，两者可以配合使用。

| 能力 | 使用方式 |
| --- | --- |
| 任务补全、图片路径补全 | 在 JSON/JSONC 编辑器中输入对应字段并触发补全 |
| 跳转定义、查找引用 | 在任务名或引用上使用 VS Code 的跳转/引用命令 |
| 悬停与内联提示 | 将鼠标悬停在任务、路径或 locale key 上 |
| 诊断 | 查看编辑器波浪线和“问题”面板中的任务、图片路径与配置错误 |
| Code Lens | 在任务或资源附近使用切换 resource、locale、执行任务等快捷操作 |
| 文档链接与工作区符号 | 点击资源路径，或使用 VS Code 的符号搜索跨文件定位 |
| Code Action | 对可提取文本使用快速修复，将内容移动到 locale 文件 |

MSE 不会把 MaaFramework Pipeline V1 自动转换为 V2。V1 与 V2 可以在同一 Pipeline 中共存；需要转换或调整结构时，请在 MPE 或文本编辑器中明确修改。

## MPE 节点导航

MSE 在 `mpe:init` 中声明 `hostNodeNavigation: true`，并处理 MPE 的 `mpe:navigateNodeRequest`。该能力只用于 External 节点：MSE 在当前资源中查找节点，打开目标 Pipeline 文件并定位，然后以相同 `requestId` 返回 `mpe:navigateNodeResult`。

Anchor 节点不会发送导航请求。MSE 随 `mpe:loadPipeline` 提供资源级 Anchor 定义；MPE 只合并其中的跨文件记录，当前文件以画布中的实时未保存状态为准。Anchor 定义弹层在 iframe 中为只读。

## 控制与调试工具

MSE 控制面板提供 MPE iframe 不具备的本地能力：

- 选择 controller、resource 和 task
- 启动、暂停、继续和停止任务
- 管理 MaaFramework 版本与下载源
- 连接控制器并获取截图
- 使用截图裁剪、OCR、模板匹配和识别测试工具
- 在启动面板查看执行状态、断点、识别详情和日志分析结果

建议的配合流程是：

1. 在 MSE 控制面板选择当前资源和控制器。
2. 在 MPE 中调整节点与字段，并使用“保存到 MSE”同步回 VS Code 文档。
3. 在 MSE 中执行任务或打开节点级辅助工具验证结果。
4. 如果文本文件又发生变化，回到 MPE 使用“从 MSE 同步”后继续编辑。

## 常用命令参考

按 `Ctrl+Shift+P`（macOS 使用 `Cmd+Shift+P`）打开 VS Code 命令面板，搜索以下命令：

| 命令 | 用途 |
| --- | --- |
| 在 MPE 中打开 | 将当前受支持的 MaaFramework Pipeline 打开到 MPE iframe 面板 |
| Maa: 展示控制面板 | 聚焦 MSE 控制面板 |
| Maa: 执行任务 | 选择并执行当前资源中的任务 |
| Maa: 执行 interface | 执行当前 interface 配置的任务 |
| Maa: 截图 | 截取当前控制器画面并保存到资源项目的 `debug/screenshot` |
| Maa: 打开截图工具 | 打开截图、裁剪、OCR、模板匹配与识别测试工具 |
| Maa: 选择 MaaFramework 版本 | 下载或切换 MSE 使用的 MaaFramework 版本 |
| Maa: 选择下载源 | 选择 MaaFramework 版本下载的 registry 镜像 |
| Maa: 打开插件日志 | 打开 MSE 扩展日志，排查资源识别、运行或 MPE 桥接问题 |

命令的显示名称会随 VS Code 语言设置变化；需要给命令绑定快捷键时，可在 VS Code 的键盘快捷方式面板中搜索对应命令。

## 常见问题

### 看不到“在 MPE 中打开”

先确认以下项目：

1. 已在 VS Code 中打开包含 `interface.json` 或 `interface.jsonc` 的工作区。
2. 当前文件扩展名为 `.json` 或 `.jsonc`，且位于已识别的 MaaFramework 资源路径。
3. 当前文件不是 `default_pipeline.json`，也不在隐藏目录中。
4. 当前工作区不是 MaaAssistantArknights 模式。

重新激活当前编辑器或等待 MSE 资源扫描完成后，再从命令面板搜索“在 MPE 中打开”。

### MPE 面板显示 URL 无效或空白

检查 `maa.pipelineEditorUrl`：生产地址使用 HTTPS；本机开发地址只允许 localhost、`127.0.0.1` 或 `[::1]` 的 HTTP。MSE 会自动生成 iframe 参数，不要把 Webview 地址或不受信任的协议填入该设置。

### MPE 提示 Pipeline 或配置加载失败

- 检查 Pipeline 是否是合法 JSON/JSONC。
- 如果同目录存在 `.{文件名}.mpe.json`，检查它是否是合法 JSON/JSONC。
- 确认 sidecar 包含 `file_config` 和 `node_configs`，且这些字段都是对象。
- 如果不需要 sidecar，可以先备份后移除它，再重新打开文件。

### 保存按钮不可用或保存失败

MPE 必须先成功加载当前文档才能保存。先修复 Pipeline/sidecar 并点击“从 MSE 同步”。如果提示文档已修改，选择同步以保留外部修改，或确认后使用 MPE 内容覆盖。

### 保存后磁盘文件没有立即变化

“保存到 MSE”首先更新 VS Code 的 `TextDocument`，并保留正常的 dirty 状态；请在 VS Code 中再次执行普通保存，将未保存文档写入磁盘。

### MPE 中无法使用截图、OCR 或运行功能

这是嵌入模式的正常边界。MPE iframe 不连接 LocalBridge，请使用 MSE 控制面板、截图工具和启动面板；运行功能还需要正确配置 MaaFramework 版本、控制器和资源。

### External 节点无法跳转

确认 MSE 与 MPE 使用兼容的 1.x `mpe-embed` 协议，并且 MSE 在 `mpe:init.payload.capabilities` 中发送了 `hostNodeNavigation: true`。能力缺失时 MPE 不会发送导航请求；能力已声明但定位失败时，检查 MSE 扩展日志中的节点名、资源层和目标文件解析结果。

Anchor 在 iframe 中不可跳转属于预期行为。其弹层用于核对当前文件实时定义和同一资源中的跨文件定义。
