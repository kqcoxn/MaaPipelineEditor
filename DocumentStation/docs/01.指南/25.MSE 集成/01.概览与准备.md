[Maa Support Extension（MSE）](https://github.com/neko-para/maa-support-extension) 是面向 VS Code 的 MaaFramework 开发扩展。MSE 提供资源分析、语言服务、运行控制、截图与调试辅助；MaaPipelineEditor（MPE）则以 iframe 形式嵌入 MSE，负责 Pipeline 的可视化编辑。

本章专门介绍在 MSE 中使用 MPE 的安装准备、编辑流程、功能边界与故障排查。若您需要把 MPE 嵌入其他应用，请参考[iframe 嵌入与通信](/guide/other/emb-protocol)。

## MSE 与 MPE 的分工

| 组件 | 主要职责 |
| --- | --- |
| MSE | 识别 MaaFramework 资源、读取 VS Code 文档、提供语言服务与运行工具，承载 MPE iframe，并处理 iframe 发起的跨文件节点导航 |
| MPE | 提供流程图画布、节点、字段、连接、模板、布局和 Pipeline 导入导出能力 |
| VS Code | 管理工作区、文本编辑器、撤销/重做、未保存状态和最终的磁盘保存 |

MPE iframe 不连接 MPE LocalBridge。设备连接、截图、OCR、任务运行和流程调试等能力由 MSE 的控制面板、启动面板与截图工具提供。

MSE 会在 iframe 握手中声明宿主节点导航能力。External 节点的目标查找、文件打开与定位由 MSE 完成；Anchor 在 iframe 中只展示定义位置，不执行跳转。

## 适用范围

MSE 本身同时面向 MaaFramework 与 MaaAssistantArknights 项目，但 MPE 集成只面向 **MaaFramework Pipeline**。MaaAssistantArknights 项目会被 MSE 识别为另一种资源模式，不能通过 MPE iframe 打开。

MPE 打开入口需要同时满足以下条件：

- 当前文件是本地文件，扩展名为 `.json` 或 `.jsonc`
- 文件位于 MSE 已识别的 MaaFramework 资源层中
- 文件不是 `default_pipeline.json`
- 文件路径不在以 `.` 开头的隐藏目录中
- 当前工作区不是 MaaAssistantArknights 模式

MSE 会递归查找工作区中的 `interface.json` 或 `interface.jsonc` 来识别资源。扫描时会跳过 `node_modules`、`MaaUtils`、`MaaDeps` 以及以 `.` 开头的目录。

## 准备工作

### 安装 MSE

1. 使用 VS Code 扩展面板搜索 **Maa Pipeline Support**。
2. 确认发布者为 `nekosu`，安装并启用扩展。
3. MSE 的扩展标识为 `nekosu.maa-support`，最低支持 VS Code `1.100.0`。

也可以从 [MSE GitHub 仓库](https://github.com/neko-para/maa-support-extension)获取发行信息与源码。

### 准备 MaaFramework 工作区

1. 在 VS Code 中打开包含 MaaFramework 资源的工作区。
2. 确认资源目录中存在 `interface.json` 或 `interface.jsonc`。
3. 确认目标 Pipeline 文件位于资源目录的 `pipeline` 路径中。
4. 如果还需要运行任务、截图或 OCR，再在 MSE 控制面板中配置控制器、资源与 MaaFramework 版本。

仅使用 MPE 编辑 Pipeline 时，不需要额外启动 MPE LocalBridge。
