## 配置 MPE 地址

MSE 默认使用 MPE 稳定版地址：

```text
https://mpe.codax.site/stable/
```

如需使用自行部署的 MPE，在 VS Code 设置中修改 `maa.pipelineEditorUrl`：

```json
{
  "maa.pipelineEditorUrl": "https://your-mpe.example.com/stable/"
}
```

地址规则如下：

- 生产环境必须使用 `https:`
- 本机开发可以使用 `http://localhost`、`http://127.0.0.1` 或 `http://[::1]`
- MSE 会自动追加 `embed=true` 与 `origin=vscode-maa`，不需要手动拼接
- URL 无效或协议不安全时，MPE 面板会显示错误，不会继续建立连接

## 打开 Pipeline

MSE 提供四种打开入口：

| 入口 | 操作 |
| --- | --- |
| 文件资源管理器 | 右键受支持的 `.json` 或 `.jsonc` 文件，选择“在 MPE 中打开” |
| 编辑器正文 | 打开 Pipeline 文件后右键，选择“在 MPE 中打开” |
| 编辑器标题栏 | 在当前 Pipeline 编辑器的标题栏选择“在 MPE 中打开” |
| 命令面板 | 按 `Ctrl+Shift+P`（macOS 使用 `Cmd+Shift+P`），搜索“在 MPE 中打开” |

同一个文件重复打开时，MSE 会复用已有的 MPE 面板；不同文件会分别创建面板和编辑状态。面板标题使用 `MPE: 文件名`。

## 加载流程

打开后，MSE 会按以下顺序将文件交给 MPE：

1. 读取当前 VS Code `TextDocument` 的内存内容，因此尚未保存的文本修改也会被加载。
2. 创建承载 MPE 的 Webview，并通过 iframe 完成握手。
3. 解析当前 Pipeline JSON/JSONC，并将 Pipeline 对象与当前资源的 Anchor 定义列表发送给 MPE。
4. MPE 载入成功后显示完整编辑器。

如果 Pipeline 或 MPE 分离配置无法解析，MPE 会保留错误状态，并在成功加载前禁用保存，避免空画布覆盖源文件。

Anchor 定义列表来自 MSE 当前资源的 `InterfaceBundle.topLayer.getAnchorList()`。MSE 使用每条记录的 `belong` 作为定义 Anchor 的 Pipeline 节点名，并标记定义所属文件是否为当前文件。

## 编辑与保存

在 MPE 中可以正常使用画布、节点、字段、连接、模板、搜索和布局等编辑能力。

### 节点导航

- External 节点：MPE 直接请求 MSE 在当前资源中查找目标节点；MSE 负责打开对应文件并定位。MPE iframe 不搜索本地 Tab、不连接 LocalBridge，也不会在 MSE 返回失败后改走本地逻辑。
- Anchor 节点：iframe 中不提供跳转。节点上的定义弹层仍会显示当前画布实时解析出的当前文件结果，并补充 MSE 提供的跨文件定义；列表项只读。

如果 MSE 未声明宿主节点导航能力，External 跳转入口会禁用并提示当前宿主不支持该操作。

### 保存到 MSE

点击 MPE 工具栏中的“保存到 MSE”，或在 MPE 中按 `Ctrl+S` / `Cmd+S`：

1. MPE 将当前画布编译为 Pipeline 数据并请求 MSE 保存。
2. MSE 检查源文档是否在加载后被其他操作修改。
3. MSE 使用 VS Code `WorkspaceEdit` 更新当前 `TextDocument`。
4. 保存结果返回 MPE，成功后清除 MPE 的未保存状态。

“保存到 MSE”是将画布同步回 VS Code 文档，并不直接绕过 VS Code 写磁盘。文档仍会遵循 VS Code 的未保存状态、撤销/重做和普通保存语义；需要写入磁盘时，请在 VS Code 中正常保存该文档。

### 从 MSE 同步

如果您在 VS Code 文本编辑器、其他工具或外部流程中修改了源文件，请点击“从 MSE 同步”。MSE 会重新读取当前 `TextDocument` 的最新内存内容，解析成功后重新加载 MPE，并重置本次会话的撤销历史与未保存基线。

不要在 MPE 尚未同步时直接覆盖外部修改。如果保存时检测到文档版本冲突，MPE 会提供从 MSE 同步或使用当前 MPE 内容强制覆盖的选择。

## MPE 分离配置

MSE 支持将 MPE 的布局和编辑器配置保存在 Pipeline 同目录的 sidecar 文件中。以 `fight.jsonc` 为例：

```text
pipeline/
├── fight.jsonc
└── .fight.mpe.json
```

规则如下：

- 没有 `.fight.mpe.json` 时，按集成配置处理，配置随 Pipeline 一起保存
- sidecar 存在且内容有效时，MSE 会在加载时合并配置，保存时同时更新 Pipeline 与 sidecar
- sidecar 至少需要包含 `file_config` 和 `node_configs` 对象
- sidecar 存在但 JSON/JSONC 损坏或字段类型错误时，MPE 会拒绝加载，不会静默丢弃布局
- sidecar 主要保存节点位置、外部节点、锚点、便签和分组等画布派生数据，不应当手动改写为业务 Pipeline 内容

MSE 会通过一次 `WorkspaceEdit` 同时更新 Pipeline 与 sidecar，避免把 MPE 配置标记写入 Pipeline 任务对象。

## 使用边界

- MPE iframe 只负责当前文件的可视化编辑，不提供多文件 Tab、跨文件搜索、跨文件自动完成或与文本编辑器实时光标双向同步；External 节点仅支持由 MSE 执行的单向宿主导航
- MPE iframe 不连接 LocalBridge；设备、截图、OCR、任务运行和流程调试请使用 MSE 对应面板
- MSE 负责当前 Pipeline 文件的加载、保存和同步，MPE 不应被理解为独立的文件管理器
- MPE 保存前必须先完成一次成功加载；加载失败时先修复源文件或 sidecar，再重新同步
