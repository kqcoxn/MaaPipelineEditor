编译器负责将 MPE 中的流程图转换为 v2 标准的 Pipeline，即“导出”过程。

## 字段编译准则

Pipeline 协议的每个字段有一个或多个可接受的参数类型。编译时，MPE 按顺序尝试该字段支持的类型，采用第一个匹配成功的结果。

整体遵循“复合结构优先、列表优先于对应单值、具体类型优先于通用类型”的顺序。常用类型的优先级与匹配标准如下；字段不支持的类型会被跳过，具体候选顺序由该字段定义确定。

| 优先级 | 类型 | 匹配标准 |
| :----: | :--- | :--- |
| 1 | 位置复合数组 | 支持坐标、`true` 和节点引用组成的位置列表 |
| 2 | XYWH 四元组数组 | 每项为 `[x, y, w, h]`；单个四元组可封装为一项 |
| 3 | XYWH 四元组 | 四个整数，支持省略外围方括号 |
| 4 | 整型二元组 | 两个整数 `[x, y]`，支持省略外围方括号 |
| 5 | 字符串键值对数组 | 每项为两个字符串组成的数组；`replace` 也接受单条字符串二元组 |
| 6 | 字符串键值对 | 明确的字符串二元组 `["a", "b"]`，不按逗号拆分文本 |
| 7 | 二维整型数组 | 各行长度一致的整型数组，颜色字段也接受一维整型数组 |
| 8 | 浮点数组 | 有限数值组成的数组，支持英文逗号分隔的数值简写 |
| 9 | 整型数组 | 整数组成的数组，支持英文逗号分隔的数值简写 |
| 10 | 字符串数组 | 按元素处理字符串，不拆分元素内容 |
| 11 | JSON 对象数组 | 各元素为对象或可按标准 JSON 解析的对象文本 |
| 12 | 布尔值 | `true` / `false`；仅支持 `true` 的字段不接受 `false` |
| 13 | 浮点值 | 可转换为数值的单值 |
| 14 | 整型 | 可转换为整数的单值 |
| 15 | JSON | 按字段约定接受 JSON 值，对象文本使用标准 JSON 语法 |
| 16 | 字符串 | 在字段支持字符串时，作为其他候选类型之后的匹配结果 |

例如，点击目标依次尝试 XYWH 四元组、整型二元组、`true`、字符串；模板匹配阈值先尝试浮点数组，再尝试浮点单值。OCR `expected` 只在字符串数组与字符串之间匹配，不把数字文本转换为数字。

混合类型按元素保留语义：神经网络 `expected` 的整数与字符串分别表示分类下标和标签名；识别组合中的字符串与对象分别表示节点引用和内联节点。`focus` 直接保留原始 JSON 值及类型，不参与上述类型推断。

数值输入必须完整有效。空项、中文逗号、数字内部空格和嵌套结构不能当作一个数字解析。JSON 使用标准 JSON 语法；普通文本、正则、节点名中的标点、引号和空格属于内容。

## 常用字段说明

### 正则编辑方式

在设置的「导出 → 文件格式 → 正则编辑方式」中，可以选择 OCR `expected`、`replace`、文字识别验证窗口及 PI 输入校验 `verify` 表单的写法：

- **原始正则**：输入 `\d+`，保存到 JSON 时自动写成 `"\\d+"`。
- **JSON 正则**：输入 `\\d+`，不加外围双引号；文本内的双引号写成 `\"`。失焦时解析转义，无效输入会在文本框下提示且不应用，保存仍使用上一次有效值。

切换编辑方式只改变显示，不改变已保存的正则内容。导入文件和 OCR 快捷工具回填的内容也会按所选方式显示。节点 JSON 编辑器始终使用标准 JSON，不受此设置影响。`replace` 每条规则分别编辑匹配正则和替换文本，两者均遵循所选转义方式。其他普通文本字段、神经网络分类标签不受影响。控制器窗口正则等完整 JSON 源码编辑区始终遵循 JSON 语法。读取文件时仅进行标准 JSON 解析，内部保留原始字符串，不会因当前编辑方式而额外转义或反转义。

### 神经网络预期结果

`NeuralNetworkClassify` 和 `NeuralNetworkDetect` 的 `expected` 支持分类下标、`labels` 中的标签名及混合数组，例如 `[0, "猫"]`。数字形式的标签名需要带引号，例如 `"123"`；整数 `123` 表示分类下标。

### 应用动作与节点通知

Win32 的 `StartApp.package` 使用可执行文件命令行，含空格的程序路径需用双引号包裹。`StopApp.package` 填进程文件名（如 `game.exe`）时会终止所有同名进程；留空时终止当前控制器窗口所属进程。ADB 控制器仍使用包名或对应启动入口。

`TouchDown` 和 `KeyDown` 支持 `auto_up` 布尔字段（默认 `false`）。启用后，在任务停止、正常结束或控制器销毁时自动抬起仍按住的触点或按键；已通过 `TouchUp` / `KeyUp` 释放的输入不会重复抬起。此字段不用于 `TouchMove` / `KeyUp`。

`focus` 接受任意 JSON，导入导出保留原始类型及空值。使用 PI 消息模板字典时，各消息可以使用字符串，或包含可选 `content`、`display`、`trace` 的对象。允许仅设置 `{"trace": true}`。`trace` 控制支持遥测的客户端是否上传节点结果；MPE 保留此字段，不执行遥测上传。

## 语法糖

MPE 提供以下便捷输入方式，适用于字段面板；节点 JSON 编辑器和导入文件使用标准 JSON。

### 时间单位

时间输入框支持 `ms`（毫秒）和 `s`（秒）：`1.5s` 保存为 `1500`，`200ms` 保存为 `200`。不写单位时按毫秒处理。失焦或按回车后提交，输入框显示转换后的整数毫秒。

适用于延迟（`pre_delay`、`post_delay`、`repeat_delay`）、识别间隔 `rate_limit`、超时（`timeout`、`shell_timeout`）、长按和滑动的 `duration`、滑动停留 `end_hold`，以及等待画面静止的时间值和其 `time`、`rate_limit`、`timeout` 子字段。滑动时间列表的每一项均可独立使用单位。

时间必须能精确转换为非负整数毫秒，例如 `1.001s` 为 `1001`；`0.0001s`、`1.1ms` 和数学表达式不接受。顶层 `timeout`、`shell_timeout` 还支持 `-1` 或 `-1ms` 表示无限等待。无效输入会在输入框下提示，保存仍使用上一次有效值。普通字符串、自定义 JSON 和 MultiSwipe 的 JSON 对象不进行通用时间单位替换。

### 粘贴完整数组

在列表字段的输入框中粘贴完整的标准 JSON 列表，会自动替换该字段的全部列表项，无需额外点击按钮：

- 阈值列表：`[0.7,0.8]`。
- 颜色列表：`[[0,0,0],[100,100,100]]`。
- OCR 期望文本：`["开始","确认"]`。
- 时间列表：`["1.5s","200ms"]`，保存为 `[1500,200]`。

只有所有项的类型与结构都符合当前字段时，才会自动替换。普通文本、无效 JSON 或结构不符的数组仍按普通粘贴处理，不会触发整表替换。粘贴 `[]` 可清空列表，清空后可通过「添加一项」继续编辑。

批量粘贴始终遵循标准 JSON 转义，不受正则编辑方式设置影响。例如匹配正则 `\d+` 在 JSON 数组中写为 `["\\d+"]`。逗号、换行分隔的普通文本不会自动拆分。单个坐标、颜色数组或替换规则不触发整表替换；批量填写这些字段时使用嵌套列表。

### 单个复合值封装

列表字段能明确识别单项结构时，可直接粘贴一项：颜色列表中的 `[0,128,255]`、坐标区域列表中的 `[100,200,30,40]`、位置列表中的 `[100,200]`，都会作为一条完整的编辑项展示。OCR `replace` 的 `["匹配正则","替换文本"]` 同样作为一条规则。

只有数字坐标或明确的字符串二元组按所属字段进行封装；普通字符串列表保持原样。例如位置列表中的 `["1","2"]` 是两个节点引用。

### 数值列表省略方括号

- 坐标可输入 `200,300,1,1` 或 `[200,300,1,1]`，导出为 `[200, 300, 1, 1]`。支持点坐标的字段也可输入 `200,300`。
- 颜色上下限等二维数值列表，每行可输入 `0,128,255`，导出时作为一个内层数组。
- 整型和浮点列表使用明确的数值输入；文本形式的数值列表使用英文逗号分隔，允许数字两侧的空白，例如 `0.7, 0.8`。

### 列表逐项编辑

列表字段提供添加、删除元素的操作，每个输入框对应一个元素；坐标、颜色等复合元素可在同一框内填写。字符串元素中的逗号不会拆成多个元素。

OCR `replace` 的每条规则分别填写匹配正则和替换文本。JSON 中使用 `["匹配正则", "替换文本"]` 或多条规则组成的二维数组，内容中的空格、方括号、引号和中英文逗号均保留。
