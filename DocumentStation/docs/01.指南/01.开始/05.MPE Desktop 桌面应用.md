# MPE Desktop 桌面应用

MPE Desktop 提供 Windows x64 与 macOS Apple Silicon 桌面工作台，由启动器和编辑器窗口组成。Linux 可使用 Web Editor 与 mpelb。

## 准备环境

从 [GitHub Releases](https://github.com/kqcoxn/MaaPipelineEditor/releases) 获取对应平台的 MPE Desktop 安装包。首次打开时可以检查环境，也可以跳过。

在「环境管理」中检查、安装或修复环境。缺少环境时，首次检查会安装最新稳定版；已有环境会展示其实际状态。安装完成后可以离线打开编辑器。

MPE Desktop 复用全局 mpelb，不为每个项目安装独立后端。版本切换会同时改变终端使用的 mpelb。

仅通过脚本安装的 CLI 环境不包含本地 Editor。切换到 MPE Desktop 后，在环境管理中安装配套版本即可补齐 Editor；已安装的 Editor 会随之后的 CLI 环境更新保持同版本。单独修复运行依赖不会重新下载 Editor。

## 添加与启动项目

在「项目管理」中添加已有目录，然后选择项目并点击「启动编辑器」。目录会保留在列表中，后续可以直接选择。移除项目只移除登记，不会删除磁盘文件；目录移动后可以重新定位。

启动器自动启动所选目录对应的 mpelb 并连接编辑器。已有其他 mpelb 服务时会显示冲突，不自动连接；选择「中断现有服务并重新连接」会停止原服务及其任务，再启动新的编辑会话。正常停止超时后才能选择强制结束。

重复打开 MPE Desktop 会提示已有实例，并退出本次启动。

## 版本与更新

在「环境管理」中点击「更新日志」，可以切换版本查看新功能、优化与修复，并标识当前已安装版本。已收录的历史日志支持离线阅读；尚未收录的新版本会联网获取发布说明，获取失败时可以重试或打开发布页面。查看日志不会改变安装版本。

选择的是一组 MPE 版本，Editor 与 mpelb 始终保持一致。桌面端自身版本可以与这组版本不同。MPE Desktop 按桌面修订号判断自身更新：仅前后端版本变化时，无需重装或重启桌面端。需要新的桌面能力时，请先在设置中更新 MPE Desktop，再获取环境版本列表。

- 自动检查 MPE 更新：启动 Desktop、开启此项及结束编辑会话时联网获取 Editor 与 LB 版本并提示新版。关闭后可在环境管理中手动检查。
- 自动安装 MPE 更新：配合自动检查使用，在完成首次配置、环境就绪且编辑器与服务停止时安装新版；关闭后仅提示，由用户手动安装。
- 固定版本：保持所选版本，自动安装不会覆盖它。
- 自动检查并更新 Desktop：独立控制启动器自身更新，在完成首次配置后，于启动、开启此项及结束编辑会话时检查；编辑器与服务须已停止。也可在设置中手动检查桌面端更新。

更新只在编辑器未运行时进行，完成后立即生效。可用版本与安装状态由启动器呈现；首次打开新版本 Editor 时显示更新日志，同版本再次打开不重复弹出。下载、校验或切换失败时保留错误信息，并恢复此前可用的环境。

开启自动检查 MPE 更新后，版本列表在启动时自动获取，不受固定版本、首次配置或环境是否已安装的限制；环境管理中的「刷新版本列表」可再次联网获取。发现前后端新版时，启动器显示当前版本、目标版本和 Editor + LB 成组更新提示；自动安装开始和完成时也会显示通知。固定版本和运行中的编辑会话只阻止自动安装，不阻止查看新版。

### 下载与代理

Windows 下，版本查询、安装器下载及运行环境下载支持系统设置中的手动代理。使用 Clash 等代理客户端时，启动代理客户端并开启「系统代理」后，再进行检查或安装；仅启动代理客户端而未开启系统代理，不会自动接管下载流量。

显式设置的 `HTTP_PROXY`、`HTTPS_PROXY` 环境变量优先于对应协议的系统代理；从终端启动 Desktop 时，安装进程会继承这些变量。`NO_PROXY` 可指定直连地址。系统代理方式不需要额外的代理启动脚本，也不要求开启 TUN。

运行环境安装器不执行 PAC 自动配置脚本或 WPAD 自动发现。使用这类配置时，请改用手动系统代理，或为启动 Desktop 的进程设置代理环境变量。代理端口取决于代理客户端的实际配置，没有固定端口。

下载超时后，先确认代理客户端仍在运行、系统代理地址与端口正确，再重试。GitHub Token 用于认证与额度管理，不能解决网络不可达。

### 版本来源与 GitHub Token

默认从站点及 GitHub Release 的静态版本索引获取可用版本，不需要 GitHub Token。自动更新检查和「环境管理」中的「刷新版本列表」都会重新联网获取版本，不因本地缓存而推迟发现新版。缓存用于联网失败时保留可查看的版本列表，不用于离线自动安装。

底部状态区和环境管理显示前后端更新进度与结果；版本来源、检查时间和诊断信息可展开「检查详情」查看。启动器设置中的「检查桌面端更新」及其结果只针对启动器自身。

列表只包含已发布完整配套清单与资源、且兼容当前桌面端和操作系统的版本。GitHub 上有 Release 不代表它可以由桌面端安装；没有符合条件的版本时，页面会明确提示暂无可安装版本。已有本地环境仍可正常使用。

可在「设置 → GitHub Token」中保存或清除 Token。配置后，版本查询优先使用 GitHub 认证 API；Token 无效、过期、权限不足或请求受限时，自动使用静态索引。Token 保存在 Windows 凭据管理器或 macOS 钥匙串中，保存后不回显，不随项目配置导出，也不发送给站点和安装包下载地址。查询公开仓库不需要写入权限。

无法联网时保留最近有效版本列表，并在环境管理页显示来源、缓存时间及本次检查状态。旧缓存不会触发自动安装；本地已安装的环境仍可启动。首次使用且没有缓存时，需要成功获取版本信息后才能浏览可选版本。后台检查失败只记录状态，主动检查失败会显示提示。

## 窗口与退出

默认启动编辑器后隐藏启动器；结束编辑后停止 mpelb 并退出整个 MPE Desktop。可以在设置中选择编辑时保留启动器，或在结束编辑后返回启动器。

编辑时关闭启动器管理窗口只会隐藏它。「退出 MPE Desktop」会处理未保存内容及运行任务，并停止托管服务。没有托盘常驻模式。

退出编辑器时，未保存文件可选择保存、放弃或取消。新文件需要选择当前项目内的保存位置；取消选择或保存失败会保留编辑会话。

## 日志查看与打包

在启动器的「日志」中选择日志来源，可查看启动器运行、环境安装和托管 LocalBridge 的输出，按关键词搜索，并手动或自动刷新。日志正文与路径可以选中复制。大文件只预览末尾 512 KB；「打包日志」仍包含完整内容，保存时可选择 ZIP 文件的位置，完成后显示保存路径。「打开目录」可查看原始日志。

LocalBridge 输出保留当前及上次会话；启动器日志超过 4 MB 后轮换保留一份历史。日志包仅收集这些日志和桌面端版本信息，不包含设置文件。需要 MFW 详细日志时，在编辑器的调试日志面板打包；编辑器的 MPE 日志导出与 MFW 日志打包均会弹出保存对话框。取消保存不会生成文件，写入失败会显示原因。

## 配置与外观

在「环境管理」中打开 mpelb 配置文件，或阅读 [进阶配置](/guide/server/advance)。编辑器中的可视化配置仍可使用。

启动器支持深浅主题和本地背景。首页提供资讯、文档及相关项目入口；网络不可用时使用缓存或内置内容。

在「设置 → 外观」中可关闭默认开启的「氛围动画」，将背景运镜、光晕、漂浮微光和天空工作流动效切换为静态显示。修改立即生效并保存，重启后仍沿用；系统开启减少动态效果时也会停用这些动效。此开关不影响轮播切换和按钮等交互反馈。
