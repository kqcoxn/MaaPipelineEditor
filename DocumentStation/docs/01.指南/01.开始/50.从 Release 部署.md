::: tip 一般用户无需自行部署
直接使用[在线编辑器](https://mpe.codax.site/stable/)即可，无需下载或部署 Web 页面。需要本地文件管理、设备连接或流程调试时，可按需[安装 LocalBridge](/guide/server/deploy)。本篇适用于希望从 Release 手动部署的用户。
:::

本文介绍如何从 [GitHub Releases](https://github.com/kqcoxn/MaaPipelineEditor/releases) 下载已构建的 Web 编辑器和 LocalBridge，并完成手动部署，无需安装源码构建环境。

## 选择下载文件

展开目标 Release 的 **Assets**，根据用途下载：

| 文件 | 用途 |
| --- | --- |
| `MaaPipelineEditor-*-stable.zip` | Web 编辑器静态资源，用于部署编辑页面 |
| `mpelb-windows-amd64.exe` | Windows x64 的 LocalBridge |
| `mpelb-linux-amd64` | Linux x64 的 LocalBridge |
| `mpelb-darwin-arm64` | macOS Apple Silicon 的 LocalBridge |
| `MaaPipelineEditor-*-docs.zip` | 文档站静态资源，使用编辑器不需要下载 |
| `MaaPipelineEditor-*-landing.zip` | 展示页静态资源，使用编辑器不需要下载 |
| `Source code` | 源码归档，不是可直接运行的 Web 构建包 |

Web 编辑器可以独立使用。需要本地文件读写、设备连接、截图或流程调试时，再部署 LocalBridge；也可以只下载 LocalBridge，配合[在线编辑器](https://mpe.codax.site/stable/)使用。前后端一起部署时，建议下载同一 Release 的文件。

## 部署 Web 编辑器

### 解压静态资源

完整解压 `MaaPipelineEditor-*-stable.zip`，保留 `index.html`、`assets/`、`monaco-editor/` 等全部文件和目录及其相对位置。

通过静态 HTTP 服务访问页面，不要直接通过 `file://` 打开 HTML。LocalBridge 提供本地通信服务，Web 页面仍需单独使用 Live Server、Nginx 等静态服务托管。

### 使用 Live Server

1. 在 VS Code 中打开解压后的目录。
2. 安装并启用 Live Server 扩展。
3. 对 `index.html` 选择 **Open with Live Server**。
4. 在浏览器中访问扩展打开的网址，例如 `http://127.0.0.1:5500/`。

### 使用网站静态服务

同一份构建包支持网站根目录和任意子目录，无需修改文件或重新构建：

- **网站根目录**：将解压内容放到静态服务根目录，访问 `https://你的域名/`。
- **网站子目录**：将解压内容放到静态服务的 `stable/` 等子目录，访问 `https://你的域名/stable/`。

目录网址应以 `/` 结尾，也可以直接访问该目录下的 `index.html`。服务器应将目录请求映射到其中的 `index.html`，并正常提供 JS、CSS 和其他静态文件。

## 部署 LocalBridge（可选）

LocalBridge 应运行在需要访问项目文件、连接设备的电脑上；Web 编辑器可以托管在其他服务器上。

### 放置可执行文件

下载对应操作系统和架构的文件，放入一个固定目录，并重命名：

- Windows：`mpelb-windows-amd64.exe` → `mpelb.exe`。
- Linux/macOS：对应平台文件 → `mpelb`，然后在该目录执行 `chmod +x ./mpelb`，赋予执行权限。

以下命令均在可执行文件所在目录运行，不要求添加 PATH。请将示例项目路径替换为自己的 MaaFramework 项目根目录。

### 准备设备与调试依赖

Release 中的 LocalBridge 文件仅包含服务程序。需要设备连接、截图、原生 OCR 或流程调试时，先停止正在运行的 LocalBridge，再执行：

::: code-group

```powershell [Windows PowerShell]
.\mpelb.exe deps reinstall
```

```bash [Linux/macOS]
./mpelb deps reinstall
```

:::

该命令会联网下载当前 LocalBridge 版本对应的 MaaFramework、MaaAgentBinary 和 OCR 模型，放到可执行文件旁的 `runtime/` 目录。Linux/macOS 需要 Bash、curl 和 unzip。移动服务程序时，请一并移动 `runtime/`。

仅使用本地文件管理时，可以跳过这些依赖。依赖准备完成后，还需启用 MaaFW，见下方连接步骤。依赖的目录结构和单独重装方法见[本地服务部署说明](/guide/server/deploy#附属运行环境)。

### 启动服务

通过 `--root` 指定要编辑的项目目录：

::: code-group

```powershell [Windows PowerShell]
.\mpelb.exe --root "D:/MaaProject"
```

```bash [Linux/macOS]
./mpelb --root "$HOME/MaaProject"
```

:::

`--root` 指向项目目录，不是 Web 编辑器的解压目录。默认服务端口为 `9066`，运行期间请保持终端打开。需要其他端口时，可在命令末尾添加 `--port 9999`。

未指定 `--root` 时，服务优先使用配置中的 `file.root`，未配置则使用启动时的工作目录。配置文件位置、便携模式及更多参数见[指令汇总](/guide/server/commands)。

## 连接 Web 编辑器与 LocalBridge

1. 启动 Web 静态服务和 LocalBridge，在运行 LocalBridge 的电脑上打开编辑器页面。
2. 若修改过 LocalBridge 端口，在编辑器配置中将本地服务端口改为相同的值。
3. 点击右上角的 **未连接本地服务** 按钮，确认状态变为 **MPE LocalBridge**。
4. 需要设备和调试功能时，进入 **配置 → LocalBridge 配置**，开启 **启用 MaaFW** 并保存配置；重启 LocalBridge 后重新连接。

自有域名托管的页面还需要加入 LocalBridge 的 `server.allowed_origins`。在可执行文件目录运行 `./mpelb config open`（Windows 为 `.\mpelb.exe config open`），在已有列表中添加页面来源，例如 `https://editor.example.com`，保存并重启服务。来源只包含协议、主机和端口，不包含 `/stable/` 等路径。默认允许本机的 `http://localhost`、`http://127.0.0.1` 页面，使用 Live Server 时可优先通过这些地址访问。

连接后，检查文件面板能否显示项目文件；使用设备功能时，再按[设备连接指南](/guide/server/device)配置控制器。

## 更新部署

- **Web 编辑器**：将新 Release 的完整静态资源包部署到原位置，避免混用不同构建包的 `index.html` 和 `assets/`，然后刷新页面。
- **LocalBridge**：停止服务，替换对应平台的可执行文件；需要 MaaFW 功能时，执行新程序的 `deps reinstall` 同步依赖，再使用原有项目路径启动并重新连接。

如果希望自动下载 LocalBridge 并准备依赖，可使用[一键安装方式](/guide/server/deploy#方式一一键安装推荐)。
