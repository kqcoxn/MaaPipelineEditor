# PERF-006 节点右键菜单与 JSON 编辑器单例

## 实施信息

- 实施日期：2026-08-31
- 适用范围：`Editor`
- 关联计划：`dev/plans/编辑器性能优化计划.md` 的 `PERF-006`
- 测试数据集：`performance-large-300.json`，300 个节点、900 条边

## 实现摘要

- `MainFlow` 使用 React Flow `onNodeContextMenu` 记录节点 ID 和屏幕坐标。
- `CanvasNodeContextMenu` 在画布根部统一渲染 Dropdown、菜单项和 JSON 编辑器；菜单配置继续复用 `getNodeContextMenuConfig`。
- 调试能力、LocalBridge 连接状态和 `mpe:edit-node-json` 事件只由单例宿主订阅一次。
- JSON 编辑器打开后按节点 ID 从 FlowStore 获取最新节点；保存时重新读取当前节点列表，避免用打开时的旧对象覆盖其他修改。
- 目标节点删除、撤销或切换文件后，单例宿主会关闭悬空菜单和编辑器；编辑器同时记录打开时的文件名，避免不同文件复用同一节点 ID 时误编辑。
- 五种节点组件移除菜单包装器、`contextMenuOpen` 状态、`getNode` 查询和每节点全局监听。

## 手动验收

需要在本机使用 100、200、300 节点数据检查：

- Pipeline、Anchor、External、Sticker 和 Group 的右键菜单、子菜单和禁用状态。
- 调试入口、从节点运行、复制、保存模板、端点位置、颜色、删除和 JSON 编辑。
- 菜单打开后拖动或修改目标节点，再保存 JSON 时不会覆盖新数据。
- 删除目标节点、撤销、重做、切换文件后没有悬空菜单或编辑器。
- 窗口边缘、缩放和平移后的右键菜单定位。

## 残余风险

- 菜单使用固定屏幕坐标锚点，窗口边缘定位依赖 Ant Design Dropdown 的边界调整，需要手动确认。
- 浏览器中的 DOM、React commit、Scripting 和 Painting 指标尚未自动化，需按 PERF-001 测量手册补充同机数据。
