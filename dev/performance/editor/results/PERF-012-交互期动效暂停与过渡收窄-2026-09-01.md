# PERF-012 交互期动效暂停与过渡收窄

## 实施信息

- 实施日期：2026-09-01
- 适用范围：`Editor`
- 关联计划：`dev/plans/编辑器性能优化计划.md` 的 `PERF-012`
- 优化目标：保留空闲状态下的边流动、节点阴影和 Anchor pulse，在画布交互争用帧预算或页面进入后台时停止装饰性持续绘制

## 实现摘要

- 新增画布动效控制器，以节点拖动、视口移动、多选节点拖动、连线、边控制点拖动和页面隐藏作为独立暂停原因。
- 单选、框选和取消选择不切换画布动画状态，选择反馈保持连续；只有选中节点发生实际位移时才进入暂停状态。
- “交互期间暂停画布动画”设置默认开启，并随画布配置保存；关闭后交互和页面后台均不再触发应用级暂停，系统的 `prefers-reduced-motion` 仍独立生效。
- 控制器直接更新画布根节点的 `data-canvas-motion` 属性。边动画和 Anchor pulse 继承同一个 CSS `animation-play-state` 变量，交互开始不触发边或节点组件重渲染。
- 多种交互重叠时，任一原因仍活跃都会保持暂停；最后一个原因结束后延迟到下一动画帧恢复，避免结束事件所在帧重新加入装饰绘制。
- 监听页面 `visibilitychange`，后台期间持续保持暂停，回到前台后恢复；组件卸载时移除监听并取消待执行动画帧。
- 系统启用 `prefers-reduced-motion: reduce` 时直接关闭边流动和 Anchor pulse，不修改编辑器配置中的动画开关。
- 画布节点高频样式不再使用 `transition: all`，仅过渡实际变化的属性；未给所有节点添加 `will-change`，避免创建大量合成层。

## 代码级性能数据

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 交互期间仍持续播放的画布无限装饰动画 | 2 | 0 |
| 页面隐藏期间仍持续播放的画布无限装饰动画 | 2 | 0 |
| `nodes.module.less` 中的 `transition: all` | 10 | 0 |
| 动效暂停导致的逐边/逐节点 React 状态更新 | 全量更新方案风险 | 0 |

两项无限动画分别为所有开启动画的边共享的 `stroke-dashoffset` 动画和 Anchor 引用高亮的阴影 pulse。这里统计的是动画种类；边动画的实际绘制实例数量仍随可见动画边数量增长，因此在交互期间统一暂停能直接消除这部分逐帧绘制竞争。

## 手动验收

- 保持边动画配置开启，在画布空闲时确认边流动效果与当前视觉一致。
- 单击选择、框选和取消选择节点，确认边流动与 Anchor pulse 不会停顿。
- 在画布设置中关闭“交互期间暂停画布动画”，确认拖动、缩放和切换标签页不再暂停；重新开启后恢复默认暂停行为。
- 分别拖动单个节点和多选节点、平移画布、滚轮缩放、拖动边控制点和拖出新连线，确认交互期间边流动与 Anchor pulse 暂停，松开后的下一帧恢复。
- 在一种交互结束前开始另一种交互，确认不会提前恢复动画；结束全部交互后确认不会永久暂停。
- 切换到其他标签页后等待，再返回编辑器，确认后台期间停止动画且返回后恢复。
- 在操作系统中启用“减少动态效果”，确认边流动和 Anchor pulse 停止，其他画布交互与阴影视觉保持可用。
- 分别悬停经典、现代、极简、Anchor、外部节点和连接 Handle，确认颜色、阴影、透明度、尺寸与位移动画仍自然，没有无关属性突变。

## 残余风险

- 自动测试验证状态机、页面可见性和静态样式边界；浏览器的实际 Painting、GPU 占用和交互帧率仍需在目标设备上通过 Performance 面板手动对比。
- 浏览器自身会对后台页面节流，但显式暂停仍用于保证恢复语义，并覆盖嵌入宿主或浏览器策略差异。
