# PERF-013 磁吸拖动期空间索引

## 实施信息

- 实施日期：2026-09-01
- 适用范围：`Editor`
- 关联计划：`dev/plans/编辑器性能优化计划.md` 的 `PERF-013`
- 优化目标：开启磁吸对齐时，将每个 pointer move 的完整候选节点扫描改为拖动开始构建、拖动期间复用的排序坐标索引

## 实现摘要

- `snapUtils` 为候选节点分别建立 left/center/right 与 top/center/bottom 排序坐标桶，查询时对拖动节点的六个对齐点执行二分查找。
- 每个轴只检查各拖动点插入位置两侧的最近坐标桶，单次查询最多检查 12 个桶；并列距离继续按原算法的节点顺序、拖动点顺序和候选点顺序决定结果。
- `useNodeSnap` 管理拖动会话，在拖动开始时构建索引，在 pointer move 中复用，在拖动结束后释放。
- 会话记录候选布局引用、拖动节点集合和视口快照。节点尺寸或拓扑提交、拖动集合变化、视口变化时会保守重建。
- 多选拖动排除全部拖动节点；拖动 Group 时递归排除 Group 子树，防止与自身子节点吸附。
- 分组节点通过 PERF-004 的坐标工具转换到画布绝对坐标。查询结果转换为统一位移后写回所有顶层拖动节点，保留 React Flow 的相对坐标模型。
- `snapOnlyInViewport` 在会话构建时使用绝对节点矩形、当前视口、画布尺寸和缩放进行过滤。

## 代码级性能数据

数据集：`performance-large-300.json`，300 节点、900 边；选择 `Perf_Node_0050`，沿 PERF-001 固定路径执行 300 次磁吸查询。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| pointer move 候选节点访问 | 87,000 | 0 |
| pointer move 对齐点/坐标桶检查 | 1,566,000 | 3,600 |
| 单次查询检查上限 | 候选数 x 18 | 12 |
| 拖动期间索引构建次数 | 每帧隐式扫描 | 1 次，会话失效时重建 |

优化后仍需在拖动开始时遍历候选节点并排序，复杂度为 `O(n log n)`；拖动中的每次查询为常数次二分查找，不随节点数量线性增长。这里的数据是确定性代码路径计数，不代替浏览器 Rendering、Painting 或帧率数据。

## 手动验收

- 开启磁吸，分别验证左/中/右与上/中/下对齐，确认最终位置和参考线一致。
- 在 0.2、1、1.5、2.5 倍缩放下拖动节点，确认磁吸阈值、参考线和写回位置正确。
- 分别开启和关闭“仅吸附可视范围内节点”，确认离屏节点只在关闭该设置时参与吸附。
- 多选两个及以上节点拖动，确认全部节点保持相对位置，且不会吸附到选中集合中的其他节点。
- 拖动 Group，确认不会吸附到自身子节点；拖动 Group 内节点对齐外部节点，确认绝对位置和参考线正确。
- 拖动普通节点进入或离开 Group，确认原有加入/脱离分组行为以及撤销、重做仍正确。
- 使用 300 节点性能数据开启磁吸连续拖动 5 秒，确认参考线稳定且交互无明显停顿。

## 残余风险

- 自动测试验证算法结果、索引生命周期和代码路径计数；浏览器主线程时间、React commit、Painting 与实际帧率需在目标设备上按 PERF-001 操作手册手动对比。
- React Flow 当前关闭节点拖动自动平移；若未来开启自动平移，视口变化会触发索引重建，应重新测量靠近视口边缘持续拖动的成本。
