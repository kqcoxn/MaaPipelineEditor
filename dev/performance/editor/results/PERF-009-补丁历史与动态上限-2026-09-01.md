# PERF-009 补丁历史与动态上限

## 实施信息

- 实施日期：2026-09-01
- 适用范围：`Editor`
- 关联计划：`dev/plans/编辑器性能优化计划.md` 的 `PERF-009A`、`PERF-009B`
- 测试数据集：`performance-large-300.json`，300 个节点、900 条边

## 实现摘要

- 历史条目由完整节点/边快照改为双向实体补丁。每个补丁保存变化实体的前后值、前后索引以及是否发生相对顺序移动。
- 数组顺序变化使用最长递增子序列识别真正移动的实体。删除或插入导致的自然索引平移不会把后续全部节点或边写入历史。
- 历史基线与当前图共享未变化实体的引用，只深拷贝补丁中实际变化的节点和边；撤销重做应用补丁时再复制目标实体，避免后续编辑污染旧历史。
- 新增单调 `graphRevision`。布局、拓扑或语义变化每次只增加一次，选择变化不增加；历史保存先比较修订号，不再为差异检测执行整图 `JSON.stringify`。
- 撤销和重做继续调用 `replace(..., skipHistory: true)`，因此节点/边索引、布局/拓扑/语义修订号和选择清理沿用同一更新路径。
- 初次导入和文件切换建立新锚点；已有历史的导入追加一个整图补丁。批量布局、粘贴、AI 命令和整图替换也使用同一补丁协议，不拆成大量 UI 历史步骤。
- 历史追加读取 `configs.historyLimit`；设置变小时立即保留包含当前状态的有效窗口并裁剪更旧条目。
- 补齐节点 replace、边重连、批量端点设置和连接路由还原的历史入口，并将对齐位置和边属性修改改为不可变更新。

## 代码级性能数据

自动测试在 300 节点、900 条边数据集上对同一个节点连续提交 100 次不同位置。默认 `historyLimit = 100`，最终历史包含一个锚点和 99 个可撤销补丁。

| 指标 | 完整快照模型 | 补丁模型 |
| --- | ---: | ---: |
| 历史条目总数 | 100 | 100 |
| 可撤销变化条目 | 99 | 99 |
| 每条单节点移动包含的节点 | 300 | 1 |
| 每条单节点移动包含的边 | 900 | 0 |
| 100 条历史的序列化体积 | 20,518,200 字节 | 74,271 字节 |
| 相对体积 | 100% | 0.36% |

测试输出：

```text
[PERF-009] 300-node/100-move history: 20518200->74271 serialized bytes, entries=100
```

完整快照体积使用同一导入后图的 `{ nodes, edges }` 序列化长度乘以历史条目数估算；补丁体积直接序列化实际 `historyStack`。该数据用于比较历史数据结构，不等同于浏览器 JavaScript Heap 的精确对象占用。

## 自动验证

- 历史补丁定向测试：删除索引平移、相对顺序移动、300 节点单移动、边属性不可变性、导入、撤销分支、等价更新和动态上限均通过。
- 性能数据集测试：300 节点连续 100 次移动的 99 个保留补丁均只包含一个节点，补丁历史体积低于完整快照估算的十分之一。

## 手动验收

需要在本机检查：

- 依次执行节点创建、删除、拖动、字段编辑、JSON 编辑、复制粘贴和自动布局，再逐步撤销、重做，图内容和操作顺序正确。
- 创建分组、调整尺寸、加入/移出节点、解散分组后逐步撤销、重做，父子关系、相对位置、尺寸和层级顺序正确。
- 添加、删除、重连连接，修改属性与顺序并还原连接路径后逐步撤销、重做，端点、标签、属性和边顺序正确。
- 在已有画布上导入 Pipeline 后可以一步撤销回导入前；切换文件后不能撤销到上一文件。
- 将历史上限分别设置为 10、100、1000，连续操作超过上限后只保留配置数量；降低上限后撤销按钮和可撤销次数立即更新。
- 在 300 节点图连续移动 100 次后观察内存和操作结束停顿，撤销、重做期间画布无明显异常。

## 残余风险

- 序列化体积能证明历史数据量级下降，但浏览器 Heap、GC 暂停和 React commit 仍需按测量手册在同一设备补测。
- 整图导入、自动布局和 AI 批量修改的补丁大小仍与实际变化实体数量成正比；这是保留单步撤销所需的数据，不再额外保存未变化实体。
- 历史上限允许设置到 10000。大量整图操作仍可能占用可观内存，实际项目应根据图规模选择合理上限。
