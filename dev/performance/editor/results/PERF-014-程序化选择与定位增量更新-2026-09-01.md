# PERF-014 程序化选择与定位增量更新

## 实施信息

- 实施日期：2026-09-01
- 适用范围：`Editor`
- 关联计划：`dev/plans/编辑器性能优化计划.md` 的 `PERF-014`
- 优化目标：搜索、Anchor、节点列表、日志、调试、业务架构、跨文件和宿主定位只更新旧选择与新目标，不再为整图节点生成 select change

## 实现摘要

- FlowStore 新增 `selectNodeIds(nodeIds, options)`，以当前节点/边选择索引和目标 ID 集合的差集生成 `NodeChange`、`EdgeChange`。
- action 仅取消不再选中的旧节点和旧边，并仅选中新加入的目标；请求与当前集合相同时直接返回。
- 变更提交后统一刷新 `selectedNodes`、`selectedEdges`、`targetNode`、选择索引和 Anchor 引用高亮，保留 React Flow 选择事件以外的业务状态语义。
- 标签定位使用 `nodeIdsByTypeAndLabel` 查找 ID，单节点定位使用 `nodeById` 读取目标；业务架构和操作日志按目标 ID 数量查询，不再扫描完整节点数组。
- 共享导航服务统一单节点 `setCenter` 和多节点 `fitView`。单节点优先读取 React Flow 运行时绝对矩形，缺失时使用父链坐标索引，支持 Group 内节点。
- 业务架构关闭弹窗后的 120ms fitView、操作日志的 100ms fitView、原有缩放上限和动画时长均保持不变；嵌入宿主的 `mpe:focusNode` 仍只聚焦而不改变选择。
- 粘贴动作显式把所有新节点和随其复制的内部边设为选中，不再继承剪贴板快照的 `selected` 字段；原对象、画布视觉选择、选择数组和 ID 索引保持一致。

## 覆盖入口

- 搜索与跨文件搜索结果定位。
- 节点列表、Anchor 引用和邻接信息跳转。
- 操作日志、调试资源诊断与调试节点定位。
- 业务架构阶段批量定位。
- 跨文件服务加载/切换后的定位。
- 嵌入协议 `mpe:selectNode` 与 `mpe:focusNode`。

## 代码级性能数据

数据集：`performance-large-300.json`，300 节点、900 边；模拟从一个旧选中节点切换到另一个节点，并清理一条旧选中边。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 单选切换生成的节点 select change | 300 | 2 |
| 无旧选择时生成的节点 select change | 300 | 1 |
| 清理一条旧选中边的 edge change | 由各入口隐式处理 | 1 |
| 按 ID 获取单节点目标 | `nodes.find`，最坏 300 次访问 | `nodeById.get`，1 次 |
| 按标签获取目标 ID | `nodes.find`，最坏 300 次访问 | 至多 5 次类型标签索引查询 |

增量 action 仍交由 React Flow 的 `applyNodeChanges` / `applyEdgeChanges` 更新数组，因此数组应用成本仍与图规模有关；本阶段消除的是每个入口主动构造整图 change、无效对象处理和重复业务状态同步。这里的数据是确定性 change 数量，不代替浏览器 React commit、Rendering 或帧率测量。

## 手动验收

- 分别从搜索、节点列表、Anchor 引用和邻接面板定位节点，确认只选中目标且画布以 1.5 倍缩放居中。
- 点击操作日志和业务架构阶段，确认全部有效目标被选中，弹窗关闭后视图完整包含目标集合。
- 从调试资源体检或节点执行入口定位，确认目标节点、字段面板和调试选择同步。
- 跨文件搜索并跳转到已加载和未加载文件，确认文件切换后按标签定位正确。
- 在嵌入宿主中触发 `mpe:selectNode` 和 `mpe:focusNode`，确认前者更新选择并发出 `mpe:nodeSelect`，后者只调整视图。
- 先选择一条边，再执行任一节点定位，确认旧边取消选择且路径/字段面板状态正确。
- 对 Group 内节点执行定位，确认按画布绝对坐标居中。

## 残余风险

- 标签相同的非法重复节点仍按类型索引中的首个 ID 定位；重复节点名称由现有重复名称校验负责提示。
- 自动测试验证 change 数量和状态一致性；点击后的 React commit、Rendering 与大图体感仍需在目标设备上按 PERF-001 操作手册手动对比。
