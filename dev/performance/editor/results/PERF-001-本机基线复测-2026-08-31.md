# PERF-001 本机基线复测

## 目的与结论

本次复测用于替换“另一台电脑上的 PERF-001 数值不能直接与当前工作区比较”的限制。基线使用 PERF-004 实施前的 `b40fa372`（`chore: 暂缓视口裁剪`）临时 detached worktree；优化版使用当前工作区。两边使用同一数据集、同一 Node/Vitest 运行时和同一测试动作，工作区结束后已清理。

导入和 Store-only 拖动微基准均通过。初版 PERF-004 的 large 导入中位数比基线低约 `10.2%`，但拖动状态更新因每次位置更新维护不可变 `nodeById` Map 而出现回归；随后增加了拖动期延迟完整索引同步的缓解。这个测试不包含 React selector、组件提交、边路径计算和浏览器帧间隔，因此不能用拖动 Store-only 数值代表 PERF-004 的整体收益。PERF-004 的主要收益由窄 selector 访问量复测体现：流程标签、聚焦关系和副本查询分别减少 `99.67%`、`99.33%`、`99.67%`。

## 固定输入与动作

- 数据集：`performance-small-100.json`（100 节点、200 边）、`performance-medium-200.json`（200 节点、500 边）、`performance-large-300.json`（300 节点、900 边）。
- 导入：真实执行 `pipelineToFlow`，校验节点数、边数、坐标和自动排版调用次数。
- 拖动：large 数据集上定位 `Perf_Node_0050`，预热 30 次后执行三轮，每轮 300 次位置更新，轨迹为横向 600 px、纵向 300 px、返回起点，最后记录松手调度和状态稳定时间。
- 命令：

```bash
yarn --cwd Editor vitest run src/core/parser/performanceDataset.test.ts -t "imports|measures the 300-node drag state-update hot path" --reporter=verbose
```

优化前测试文件没有 PERF-004 selector 测试；优化后使用 `-t` 过滤到相同的四个导入/拖动测试，额外的 selector 测试不计入下表。

每个单元格中的三个数字对应测试内部三轮 300 次位置更新；外层重复三次独立进程。

| 进程 | 基线三轮总耗时（ms） | 基线更新 P95（ms） | 优化版三轮总耗时（ms） | 优化版更新 P95（ms） |
| ---: | --- | ---: | --- | ---: |
| 1 | `5.98 / 5.19 / 4.23` | 0.025 | `9.69 / 10.96 / 8.21` | 0.050 |
| 2 | `6.00 / 4.81 / 4.24` | 0.025 | `8.35 / 9.84 / 9.67` | 0.046 |

外层三轮总耗时中位数分别为 `15.40 ms`（基线）和 `27.86 ms`（优化版）；单次更新 P95 中位数增加 `0.021 ms`。松手同步调度中位数为 `0.233 ms`（基线）和 `0.221 ms`（优化版），松手状态稳定中位数为 `2.640 ms` 和 `2.136 ms`。

这组数据保留初版 PERF-004 的 Store 写入成本，验证了索引维护导致的固定开销，但没有覆盖本项消除的组件级整图扫描。位置更新期间，优化版 `semanticRevision`、`topologyRevision` 不变，相关订阅不通知；large 数据集的 selector 结构化访问量从 `270000 / 270000 / 9000` 降到 `900 / 1800 / 30`。

## DRAG-01 写入侧缓解复测

缓解方案是在所有变更均为 `position + dragging: true` 时只应用 `nodes` 数组和 `layoutRevision`，暂不复制或替换完整 `nodeById`；最终 `dragging: false` 事件再执行一次完整索引同步。这样保留拖动期间的布局更新，同时把索引维护从每个指针事件推迟到松手时。

| 进程 | 缓解后三轮总耗时（ms） | 更新 P95（ms） |
| ---: | --- | ---: |
| 1 | `7.66 / 6.57 / 4.97` | 0.035 |
| 2 | `8.12 / 5.70 / 5.37` | 0.034 |
| 3 | `7.01 / 5.68 / 8.35` | 0.029 |
| 中位数 | `7.66 / 5.70 / 5.37` | 0.034 |

三轮总耗时外层中位数为 `19.20 ms`，相对初版 PERF-004 的 `27.86 ms` 降低约 `31.1%`；相对 PERF-004 前基线的 `15.40 ms` 仍高约 `24.7%`。这说明缓解已收回大部分由不可变 Map 分支复制引入的回归，但 Store-only 写入仍有固定状态更新成本。该差异不等同于浏览器中的拖动帧率变化，selector 扩散收益和组件提交成本仍应分别观察。
