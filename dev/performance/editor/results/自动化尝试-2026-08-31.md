# PERF-001 自动化测试尝试

## 结论

状态：失败样本，不作为正式性能基线

数据集状态：该次测试使用的 1000 节点极端档已于同日废弃，后续正式基线改用 100/200/300 节点和更高边密度。本记录仅保留历史诊断事实。

生产构建可以正常启动，首次使用协议、20 题知识测试、更新日志关闭和空画布均可通过浏览器 UI 自动化完成。通过剪贴板导入 `performance-large-1000.json` 时，导入操作超过 30 秒仍未返回；随后对同一页面采集 DOM 快照，等待 120 秒仍未完成。该页面还导致同一内置浏览器中新建的空标签在 40 秒内无法生成 DOM 快照。

旧数据集的全部节点均含预置位置，文件配置为 `coordinateMode: "absolute-v1"`。按 `pipelineToFlow` 的导入分支，这会令 `isIncludePos` 为真并跳过 `LayoutHelper.auto()`；因此该次超时没有自动排版触发证据，不能归因于自动排版。

由于浏览器控制面已被持续占用，本次无法继续执行 small、medium、拖动、缩放、走线切换、列表滚动和面板开关，也无法取得 Scripting、Rendering、Painting、Long Task、React commit、Heap 与 DOM 的可比较数据。不能把自动化控制超时直接等同于页面主线程阻塞时长，因此只记录“超时”，不填造毫秒指标。

## 静态加载补充

本机 loopback 请求仅用于确认预览服务和文件体积，不代表浏览器可交互时间：

| 资源 | HTTP | 下载体积 | loopback 总耗时 |
| --- | ---: | ---: | ---: |
| `/production/` | 200 | 1475 B | 1.94 ms |
| 主入口 `index-_LlU_nhI.js` | 200 | 5,121,573 B | 27.92 ms |

生产 HTML 还会立即 preload Monaco 与 Tesseract 分块。首屏实际请求数、解析执行时间和可交互时间仍需浏览器 Performance trace，不能由 `curl` 结果替代。

## 后续要求

1. 需要扩展浏览器指标时，应在独立浏览器进程中按 small、medium、large 顺序执行，避免 large 超时污染前两档。
2. 每个数据集使用独立浏览器上下文或进程；large 导入设置独立的 watchdog，并在超时时保存已有 trace 后终止该上下文。
3. 自动采集需要能够直接输出 Chrome trace、Long Task 和 Heap 的浏览器接口。当前内置浏览器只提供 UI 控制、DOM 快照和页面日志，无法在页面失去响应后导出这些指标。
4. 本记录只保留旧数据集失败事实，不用于后续优化百分比对比。PERF-001 已以调整后的数据集、真实导入和连续拖动状态热路径完成快速自动化基线，见 `首次自动化基线-2026-08-31.md`。
