# PERF-010 分文件异步缓存

## 实施信息

- 实施日期：2026-09-01
- 适用范围：`Editor`
- 关联计划：`dev/plans/编辑器性能优化计划.md` 的 `PERF-010A`、`PERF-010B`
- 测试数据集：`performance-large-300.json`，300 个节点、900 条边

## 实现摘要

- 缓存触发从 React 组件内的选择状态防抖改为 Zustand 命令式订阅。只有 `graphRevision` 变化才在 500 ms 合并窗口后同步当前图；节点或边选择变化不会触发图复制或文件持久化。
- 当前文件记录已同步的文件名和图修订号。`saveFlow()` 只在真实图变化或文件切换时复制节点与边，并在这一同步边界移除 `selected`；配置缓存由 `configStore` 独立维护。
- Pipeline 缓存拆为文件记录和 manifest。manifest 只保存文件顺序、当前文件名和缓存协议版本；变化文件按文件名写入，关闭文件会删除对应记录。
- 正常浏览器使用 IndexedDB 读写文件记录，事务异步执行且不再对全部打开文件执行 `JSON.stringify`。旧 `_mpe_files` 缓存与 IndexedDB 不可用场景使用分文件 `localStorage` 回退，并在首次写入时完成迁移。
- 文件变化先经过 250 ms 合并，再在空闲回调中提交，空闲等待最多 1000 ms。页面隐藏、`pagehide` 和 `beforeunload` 会同步最新图并提交待写记录。
- 缓存恢复同时还原全部打开文件、文件顺序和当前文件。异步恢复期间若用户已经修改画布或文件列表，则放弃旧缓存恢复，避免覆盖新操作。
- IndexedDB 记录不完整时不接受部分结果；事务失败后回退分文件缓存。manifest 使用单调更新时间，恢复时选择 IndexedDB 与关闭前回退记录中较新的完整快照。两种存储都失败时保留待写记录，并显示配额或存储权限错误。

```text
[PERF-010] 300-node/900-edge cache serialization: all-5-files=1026151 bytes, dirty-file=205230 bytes
```

## 手动验收

需要在本机检查：

- 打开多个 Pipeline，分别编辑节点、边和文件配置；刷新页面后文件顺序、当前文件及各文件内容正确恢复。
- 只选择、取消选择、框选节点和边，确认画布操作正常，短时间内不会出现缓存写入错误提示。
- 连续拖动 300 节点图中的节点，操作结束后切换文件再切回，最终位置正确且无明显操作后停顿。
- 重命名、排序和关闭已打开文件，刷新后 manifest 中的顺序和文件集合一致，已关闭文件不会恢复。
- 在 LocalBridge 中触发文件外部修改、删除、重新加载和保存，刷新后对应标记及内容正确。
- 编辑后立即刷新或关闭标签页，再次进入时最近操作仍可恢复。
- 通过浏览器开发者工具限制站点存储或制造配额不足，确认出现明确错误提示且编辑功能本身不受影响。

## 残余风险

- 浏览器关闭流程不允许等待任意长的异步任务，因此离开页面时同时写入分文件 `localStorage` 恢复记录并启动 IndexedDB 事务；这一必要兜底仍会在关闭时同步处理尚未提交的变化文件，但不处理全部未变化文件。
- 代码级数据量可以证明工作范围从全部文件收窄到变化文件；浏览器 Long Task、IndexedDB 实际事务耗时和不同设备的存储配额仍需按测量手册在目标浏览器补测。
