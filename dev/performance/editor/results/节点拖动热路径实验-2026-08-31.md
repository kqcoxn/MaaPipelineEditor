# PERF-001 节点拖动热路径实验

## 结论

状态：拖动状态更新通过；扩展浏览器指标未取得

在 large 数据集（300 节点、900 边）上模拟 `DRAG-01`：以 60 Hz、5 秒对应的 300 次位置更新，依次完成横向 600 px、纵向 300 px并返回起点。测试真实调用 FlowStore 的 `updateNodes` 和 React Flow 的 `applyNodeChanges`。

纯状态更新成本较低，当前证据不支持把 `updateNodes/applyNodeChanges` 判定为拖动卡顿的主要来源。该实验不包含 React 订阅传播、节点和边 DOM 提交、边路径计算、Rendering、Painting、合成与帧间隔，不能替代浏览器运行时基线。

## 浏览器测量尝试

生产预览可以启动，内置浏览器也能完成导航并返回页面标题，但读取 DOM 或截图均在 30 秒内超时并导致控制会话重置。独立 Chrome 浏览器未连接，因此本次无法执行真实指针拖动，也不能取得以下指标：

- Scripting、Rendering 和 Painting
- 帧间隔、掉帧比例与最低 FPS
- Long Task 数量和最长时长
- React commit 数量和最慢提交
- 三种走线模式的边路径重算差异

浏览器控制超时不是页面拖动耗时，不能填入性能结果表。

## 后续判定重点

恢复可用浏览器后，优先在 large 数据集的 `bezier`、`smoothstep`、`avoid` 三种模式下各执行三次 `DRAG-01`。如果真实拖动仍明显卡顿，应首先比较 React commit、边路径计算、Painting 和动画开销；不要在缺少浏览器证据时提前优化纯 Store 更新。
