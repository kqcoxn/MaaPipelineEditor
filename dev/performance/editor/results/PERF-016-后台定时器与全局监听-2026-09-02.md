# PERF-016 后台定时器与全局监听

## 结论

PERF-016 已完成。Header 不再轮询 LocalBridge 状态，也不再直接注册服务回调；普通模式与 MSE 嵌入模式的 Star 提醒统一管理定时器，并在页面隐藏或组件卸载后停止唤醒。

## 实施范围

- 新增唯一的 LocalBridge 状态桥接，由服务回调写入 `wsStore`。
- App 负责状态桥接的初始化和销毁，并保留断线清理调试会话、清空控制器及重连后恢复上次控制器的行为。
- MFWProtocol 的状态订阅只保留截图请求等协议内部清理，并在重复注册或注销时释放；控制器 UI 状态不再由协议层重复写入。
- Header 的连接按钮和设备入口按字段订阅 `wsStore`，移除两份每秒轮询及组件级 LocalBridge 回调。
- 普通模式和 MSE 嵌入模式共用 `useStarReminder`。
- Star 定时器在页面隐藏时停止，恢复可见后重新开始完整提醒周期；完成或永久忽略全部目标后停止定时器。
- 删除空的 `GlobalListener` 占位组件。

| Header 活跃 WebSocket 轮询 | 2 | 0 |
| UI 层 LocalBridge 状态监听 | 3 | 1 |
| UI 层 LocalBridge 连接中监听 | 2 | 1 |
| App 与 Header 卸载后遗留状态/连接中监听 | 3 / 2 | 0 / 0 |
| 普通 Star 提醒在后台的活跃 interval | 1 | 0 |
| 普通 Star 提醒在 App 卸载后的活跃 interval | 1 | 0 |

计数范围只包含 PERF-016 指定的 App、Header、Star 提醒和 LocalBridge UI 状态同步。协议实例在应用入口初始化一次的长生命周期订阅不属于组件重复挂载路径。实时画面、新手引导和条款弹窗的 interval 均已有成对 cleanup，本次不修改。

## 生命周期验证

- StrictMode 首次 effect、清理、再次 effect 后只有 1 个 Star interval 和 1 个 `visibilitychange` 监听；最终卸载后均为 0。
- 页面初始隐藏时不创建 Star interval；切回可见时创建 1 个，重新隐藏后清除。
- LocalBridge 状态桥接连续初始化、销毁两轮，每轮状态与连接中监听均从 1 回到 0。
- MFWProtocol 切换服务实例时释放旧状态订阅，注销后新服务实例的订阅数量回到 0。
- 连接成功仍触发上次控制器自动连接；断开仍清空控制器状态和当前进程的调试会话状态。
- App 普通模式卸载时执行状态桥接取消函数。
