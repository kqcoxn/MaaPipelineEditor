# Editor 性能测量操作手册

## 1. 目标与约束

本手册用于在快速自动化基线之外补充浏览器详细指标，并在涉及 React 提交、DOM、边绘制或动画的后续性能实施单元中重复相同场景。只比较同一设备上的相对变化；不要跨设备直接比较绝对帧率或毫秒数。

测量必须使用生产构建或与生产配置等价的构建。录制期间关闭浏览器扩展、DevTools CPU/网络限速、系统录屏、后台编译和其他高负载进程。浏览器缩放固定为 100%，显示器刷新率固定，窗口尺寸固定且不最大化/恢复切换。

## 2. 环境记录

开始前在 `性能记录模板.md` 的副本中填写：

- Git 提交号与工作区是否干净。
- 操作系统、CPU、内存。
- 浏览器完整版本、屏幕刷新率、浏览器缩放和窗口 CSS 尺寸。
- 构建命令、数据集文件、seed、SHA-256、走线模式。
- LocalBridge 是否连接、是否为 iframe 模式。

首次加载指标每次使用新的无痕窗口，或在 DevTools Network 勾选 Disable cache 后硬刷新。交互指标使用已经加载完成并静置 10 秒的页面，避免把首次编译、图片请求或字体加载混入拖动结果。

## 3. 数据准备

1. 在仓库根目录执行 `yarn perf:verify`，必须全部通过。
2. 执行 `yarn build`，使用生成的生产构建进行测量。
3. LocalBridge 资源根目录选择 `dev/performance/editor`。
4. 依次打开 `datasets/performance-small-100.json`、`performance-medium-200.json`、`performance-large-300.json`。
5. 在浏览器控制台执行 `mpedev("performanceSnapshot")`，记录导入后静置状态的 DOM 数量和 Heap。Chrome 未开放 `performance.memory` 时 Heap 会返回 `null`，改用 DevTools Memory 面板的 Heap snapshot。
6. 日志场景前执行 `mpedev("preparePerformanceLogs")`，返回值必须为 1000 条后端日志和 200 条嵌入日志；日志数量与图数据集节点数独立。

每次切换数据集或走线模式后静置 10 秒，随后先录制一次预热操作但不记入结果，再执行 3 次正式录制。报告使用 3 次中位数，同时保留最差一次的最长任务。

## 4. 统一录制设置

Chrome DevTools Performance：

- 保持 CPU 为 No throttling，Network 为 No throttling。
- 关闭 Screenshots，开启 Memory；录制首次加载时再开启 Network。
- 每次只录制一个场景，操作前后各留 1 秒空白区间。
- 在 5 秒操作区间汇总 Scripting、Rendering、Painting。
- Long Task 定义为主线程单任务超过 50 ms；记录数量与最长时长。
- 记录交互结束后 1 秒内是否出现历史保存、序列化或缓存写入导致的长任务。

React 提交数据使用 React DevTools Profiler 单独录制同一动作。记录 commit 数量、最慢 commit 和总渲染时长。若当前生产构建不支持 Profiler，报告必须写“不适用：生产构建未启用 profiling”，不能用开发模式数据替代生产数据。

Heap 与 DOM：操作前后分别运行 `mpedev("performanceSnapshot")`。需要精确 Heap 时，在 Memory 面板执行 GC 后拍 Heap snapshot；不要把一次 GC 的停顿记入交互录制。

## 5. 固定场景

除特别说明外，以下场景在 large 数据集的 `bezier`、`smoothstep`、`avoid` 三种走线模式各执行一次。可用 `mpedev("setConfig", { key: "edgePathMode", value: "bezier" })` 精确切换。

| 编号 | 固定操作 | 操作边界 |
| --- | --- | --- |
| LOAD-01 | 首次加载 | 新无痕窗口打开生产页面，从发起导航录到画布可交互并静置 2 秒。记录请求数、传输体积和可交互时间。 |
| DRAG-01 | 普通节点拖动 | 搜索并定位 `Perf_Node_0050`，按连续“横向 600 px、纵向 300 px、返回起点”的轨迹拖动 5 秒，松开后继续录 1 秒。 |
| DRAG-02 | Group 拖动 | 定位 `Perf_Group_T1_001`，用同一轨迹拖动整个 Group 5 秒，松开后继续录 1 秒。 |
| VIEW-01 | 缩放和平移 | 2 秒从当前缩放放大一档，1 秒平移 600 px，2 秒缩回原比例；不要触发 `fitView`。 |
| SELECT-01 | 框选移动 | 在未分组的规则网格区域框选连续 100 个普通节点，整体横向移动 300 px 后松开并继续录 1 秒。报告实际选中数，非 100 时该次作废。 |
| ROUTE-01 | 走线切换 | 依次切换 `bezier`、`smoothstep`、`avoid`，每次静置 3 秒，再执行 DRAG-01。三种结果分别记录。 |
| LIST-01 | 节点列表滚动 | 打开节点列表，从顶部用鼠标滚轮连续滚动到底部，持续 5 秒。不得使用 End 键瞬移。 |
| LOG-01 | 后端日志滚动 | 执行日志准备命令，打开后端日志的 1000 条列表，连续滚动到底部并随机展开 10 条 payload，录制 5 秒。 |
| LOG-02 | 嵌入日志滚动 | 在 iframe 模式执行日志准备命令，打开 200 条嵌入日志，连续滚动到底部并随机展开 10 条 payload，录制 5 秒。 |
| PANEL-01 | 重面板开关 | 调试、AI 历史、业务架构、节点 JSON 面板分别执行“打开、等待内容稳定、关闭”，每个面板单独录制并记录首次打开与再次打开。 |
| HISTORY-01 | 50 次编辑与撤销重做 | 对 `Perf_Node_0050` 连续提交 50 次可撤销字段修改，再连续撤销 50 次、重做 50 次；分别记录编辑、撤销、重做阶段与最大 Heap。 |

small 和 medium 数据集至少执行 LOAD-01、DRAG-01、VIEW-01、ROUTE-01；large 执行全部场景。后续单项优化只需重复与该实施单元直接相关的场景，但优化前后必须使用相同数据集和动作。三个数据集均带完整坐标，若导入时观察到自动排版，应先判定为回归并停止记录该次结果。

## 6. 结果有效性

出现以下任一情况时本次录制作废并重测：

- 数据集 SHA-256 与 `manifest.json` 不一致。
- 操作持续时间偏离 5 秒超过 0.5 秒。
- 浏览器窗口尺寸、缩放、刷新率或走线模式中途变化。
- 录制期间出现图片 404、LocalBridge 重连、热更新、系统更新或后台编译。
- SELECT-01 实际选择数量不是 100。
- 首次加载场景复用了缓存，或交互场景仍有未完成的首次资源请求。

原始 `.json`/`.cpuprofile`/Heap snapshot 可按 `日期-提交-设备-数据集-模式-场景-序号` 命名并放在仓库外；仓库只提交汇总 Markdown，避免大体积二进制污染历史。
