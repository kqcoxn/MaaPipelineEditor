# PI 管理功能规划

本文记录 MaaPipelineEditor（MPE）的 ProjectInterface（PI）管理功能方向、阶段划分与实施边界，作为后续开发的规划依据。本文属于开发规划，不代表所列功能均已实现；用户操作说明在功能落地后按需更新到文档站。

## 目标

让 PI 成为连接项目配置、Pipeline 画布和调试运行的项目管理入口，形成从理解项目、编写配置到验证运行结果的完整流程。

重点围绕资源作者的开发需求展开：

- 看清任务、选项、资源及其引用关系。
- 从 PI 任务进入画布，使用实际配置进行调试。
- 在 MPE 中编辑 PI，并准确写回源文件。

## 第一阶段落地

第一阶段以文件标签前固定的「Interface」为入口，提供独立 GUI 工作区：任务编排、选项配置、视口、日志和项目运行。页面启动仍默认进入画布，普通配置仅保存到网页缓存，GUI 与调试器运行解耦。

实现说明与验收清单见 [PI 第一阶段实现与验收](PI第一阶段实现与验收.md)。

## 第二阶段落地

PI 主文件、导入文件与语言文件共用文件面板和标签栏，按文件打开结构化编辑器或源码视图。项目级引用索引用于跨文件导航、诊断和关联修改，保存写回原始文件并检测版本冲突。

实现边界与验收流程见 [PI 第二阶段实现与验收](PI第二阶段实现与验收.md)。当前交付止于第一、二阶段。第三阶段经实现与试用后取消，相关改动已撤销；第四阶段保持取消。复杂覆盖关系和跨文件修改的影响分析交由 AI 辅助，不再建设专用交互流程。

## 规划起点


规划制定时，仓库已具备以下基础能力：

- PI 发现、读取、Schema 校验与部分语义诊断。
- `import` 合并、来源位置追踪、多语言解析和源文件监听。
- 控制器、资源与全局／资源／控制器选项的调试上下文解析。
- Agent 的调试接入与进程管理。

这些能力主要服务于读取 PI 并辅助调试。第一、二阶段在此基础上补充任务维度的运行配置和面向作者的结构化编辑；跨 PI 与 Pipeline 的全面重构及最终覆盖效果解释不再纳入开发计划。

实施时应复查现有代码，复用已落地能力；协议语义以 MaaFramework 官方文档、Schema 和源码为准。

## 功能方向

### 1. PI 项目面板

提供独立的项目入口，集中展示任务、选项、资源、控制器、Agent、预设与导入文件。

核心能力：

- 点击任务，定位对应的 Pipeline 入口节点。
- 通过已有引用诊断和源码导航检查选项定义与引用。
- 查看合并后的配置，并定位到实际定义它的源文件。
- 展示当前资源组合、加载顺序与项目诊断。

优先复用已有来源位置追踪能力。对于多文件 `import` 项目，应同时帮助用户理解合并结果和原始文件组织。

### 2. Interface GUI 运行工作区

Interface 面向项目使用者，画布与调试器面向流程开发。两者使用独立的启动、状态和日志系统，仅复用协议解析、选项控件、设备管理与 MaaFramework 底层能力。

核心能力：

- 任务勾选、排序、预设应用、嵌套选项与浏览器缓存。
- 执行前冻结整组配置，直接加载磁盘资源，顺序运行选中任务。
- 按 PI 语义在连接设备前执行适用的预任务，失败阻止运行。
- 设备视口、实时日志、进度、停止和结果反馈。
- 后台继续运行和断线后的状态同步；GUI 与调试器运行互斥。
- 「在画布中查看」作为可选开发操作，不作为运行前置条件。

覆盖顺序：任务自身 → 全局 → 资源 → 控制器 → 任务选项。GUI 不接入调试覆盖；预任务选项仅用于程序参数，不进入 Pipeline 覆盖。

### 3. PI 可视化编辑

优先覆盖任务与选项的常见编写操作，再逐步扩展其他项目配置。

首批编辑能力：

- 从画布节点创建 PI 任务。
- 编辑任务名称、入口、分组、适用资源／控制器与关联选项。
- 创建选择、开关、多选、输入等选项，编辑分支与嵌套关系。
- 调整任务顺序与默认值。

编辑范围同时覆盖资源、控制器、Agent 和项目元信息。已有预设保留应用、源码编辑与引用检查能力，不规划专用发布预设编辑器。

写入基础要求：

- 修改准确写回原始定义文件，保留 JSONC 注释、格式与字段顺序。
- 导入文件中的定义写回对应文件，不将合并结果整体覆盖到主文件。
- 对被多处定义或覆盖的内容，明确当前修改的定义位置。
- 外部编辑导致源文件版本变化时检测冲突，避免覆盖用户修改。
- 不使用普通反序列化后整体序列化的方式重写源文件。

精确写回能力作为 PI 编辑与已有引用修改共用的基础。

## 阶段划分

| 阶段 | 状态 | 交付范围与处理 |
| --- | --- | --- |
| 第一阶段 | 已完成，保留 | Interface GUI 工作区、任务编排、视口与日志，支持选择配置并运行项目 |
| 第二阶段 | 已完成，保留 | PI 精确写回、结构化编辑、源码导航和已有引用诊断 |
| 第三阶段 | 已取消，改动已撤销 | 原覆盖效果预览、完整来源链、指定分支编辑、双向引用、跨 PI／Pipeline 重构及关联事务保存不再推进 |
| 第四阶段 | 已取消 | 不建设专用客户端预览、发布预设编辑或配置组合穷举 |

第三阶段经试用后，专用界面的实际收益不足，复杂配置分析交由 AI 辅助处理。AI 集成通过下文的 Harness 能力扩展单独实施。第一、二阶段已有的编辑、引用检查与保存能力继续保留。

## 当前交付范围

**Interface → 勾选与配置任务 → 准备项目／连接设备 → 顺序运行 → 观察画面和日志。**

完成标准：用户无需进入画布或调试器，即可使用 PI 项目的任务与选项完成运行。运行不依赖源节点索引；设备缺失、配置无效、项目版本失效或运行冲突必须明确阻止，不自动改换任务或设备。

编辑流程：**打开 PI 文件 → 编辑任务与选项 → 检查引用 → 保存当前文件或关联修改 → 返回 Interface 使用已保存配置。**

覆盖最终效果解释、完整来源链、指定覆盖分支编辑和跨 PI／Pipeline 关联重构已取消。已有 Interface 配置、预设应用、PI 编辑与引用检查能力保留。远程素材预览与完整客户端交互消息不纳入当前交付范围。

## MPE Harness 的 PI 辅助

AI 辅助作为现有 Harness 的项目能力扩展，提供 PI 摘要、定义和引用查询、静态配置解析、局部修改方案、关联 PI 草稿应用及校验。默认纳入草稿，复用现有编辑器撤销与保存。实施说明和验收清单见 [MPE Harness PI 辅助实现与验收](MPEHarness-PI辅助实现与验收.md)。

第三、第四阶段维持取消。本扩展不恢复独立覆盖预览画布、指定分支编辑工作区、框架最终值求值或跨 PI／Pipeline 保存事务。

## 实施原则与参考

- 前端负责项目展示、编辑交互和画布联动，LocalBridge 复用并扩展协议解析、诊断、文件写入和运行配置能力，避免两端分别维护不一致的协议规则。
- 任务上下文作为导航、选项配置与调试的共同基础。
- 原始文档、合并后的项目视图和运行时生效配置应有明确区分；本地调试偏好与项目声明分别保存。
- 前端交互由用户手动验证，不自动启动开发服务器或进行浏览器测试；实现时按改动范围提供手测清单。
- 功能落地后，按需更新文档站，以当前可用能力指导用户操作。

参考入口见 [社区参考项目索引](社区参考项目索引.md)：

- **MaaFramework**：协议字段、合并规则与运行时语义。
- **MFAAvalonia**：任务与选项的真实客户端处理及资源项目交付后的使用体验。
- **maa-support-extension（MSE）**：PI 定义跳转、引用查找、诊断及编辑辅助。

参考项目用于核对协议与提炼实践；最终交互和实现应结合 MPE 的画布工作流与现有架构设计。
